## ✉️ 電子郵件標頭分析與釣魚郵件防禦實務

**【授課講師】**：收到這封信之後，你去看一下它的信件標題與網域名稱（Domain Name），寄信的網址跟它的網域名稱有沒有相符？如果相符的話就還好，如果不相符那就麻煩了，表示這封信件有偽冒問題。

所以信件標頭開啟可以看到很多東西：什麼時候傳送的時間、什麼時候收信的、標題是什麼。從這個地方你可以分辨出它到底是一般垃圾信，還是有惡意攻擊連結的釣魚郵件。

通常你用 Google Mail（Gmail）應該怎麼樣？應該是不太可能看到直接附帶惡意程式的信件，因為都被雲端過濾掉了。通常看到的是惡意連結，把惡意連結包裝在垃圾郵件送給你。

那當然在 Web 伺服器的記錄（Web Access Logs）上面，網站站臺其實都有 HTTP 請求（Request）跟回應（Response）封包。要求跟回應的封包上面會有 Header 標頭，標頭裡面會寫一些東西出來。如果你在分析或記錄的過程當中沒有過濾，這些東西往往會產生大量雜訊。

所以假設你今天要做一套 SIEM（資安資訊與事件管理系統），或是你要成立一個 SOC（資安維運中心），你的資料來源一定不能少，所有系統元件的日誌都要送上來。資料來源包含哪些東西？我們在這個章節能夠學到，就麻煩大家睜大眼睛注意看一下。

接下來我們來看一下第十二章第四個小節，這裡講到警告跟監視的工具。工具很多，通常我們都會去想辦法找開源免費的工具。為什麼？因為大部分商業資安工具都非常貴！只要說是商用資安產品，動輒都是六位數、七位數以上。很少有五位數字以下的，大家要理解。為什麼？因為這種資安軟體授權與導入顧問案往往專案單價極高，但問題是，你可以用開源免費的方式去把它搭建出來。

像這個地方我跟大家提醒，我們講到 SIEM 系統，SIEM 它是一個概念，就是 Security Information and Event Management（資安資訊與事件管理中心）。

它的核心概念是什麼？就是你要去彙總、統計現在所有相關的資安數據：網路流量、網站存取情況、系統資源分配情況等等一系列資料內容，呈現出戰情室面板。

傳統單位的 SOC 戰情室面板，不是只有單一螢幕，它是用電視牆、很多的螢幕，每個螢幕都出現了不同的觀察指標和記錄，顯示各種維運狀況。只要有某個部分發生問題，維運人員就可以開始介入處理。

比如這邊發現有駭客入侵的行為，假設他是對外的服務，相關聯的監控圖表就會跳出告警。大家就可以看得很清楚有人在嘗試攻擊，攻擊在什麼地方？這次是什麼？DDoS 攻擊？來自哪些 IP？系統會針對這些 IP 做圖表統計，分析這些攻擊 IP 的地理位置在什麼地方。

一開始要先採取防護措施，把這些惡意 IP 位址和流量引導到清洗中心（Scrubbing Center），或是直接在邊界防火牆封鎖阻斷掉，以維持網路對外服務的暢通。然後再去追蹤這些來源 IP 位址，雖然溯源其實蠻困難的。那這些都是從圖表上面可以即時監控看到的。

所以我才跟大家講說，大部分的 SIEM 都可以自己搭建，只要配置出自己需要用到的監控工具。那在這種工具裡面，第一件事情要先做日誌收集（Log Collection）。

日誌收集有 Agent-based（代理程式架構），怎麼做到 Agent-based？就是你的遠端受控機器要先安裝 Agent 軟體。就像昨天我跟大家講的 SNMP 或 Syslog Agent 一樣，安裝好 Agent 之後，設定好讓它把本機資料抓取並傳送過來。遠端的 Agent 可以主動推送（Push），也可以由收集伺服器定時拉取（Pull）。

接下來還有所謂的 Listener 與 Collector。Listener 就是監聽接收器，Collector 是收集器。這意思是說，監控端可以被動接收資料，任何系統的伺服器都往這邊送。如果要推送日誌，一定走標準通訊協定，像 Syslog 通訊協定標準。

大家可以去查一下，Syslog 通訊協定走的是哪一個 Port？預設 Port 是多少？這個考試常考，Syslog 預設是 UDP Port 514（加密傳輸為 TCP Port 6514）。注意喔，它是 Protocol-based，是標準的網路傳輸協定。

再來有一種偵測器（Sensor），攔截在網路流量的埠位上，接收網路攻防封包並進行流量分析，最常見的就是 NetFlow、sFlow 與 IPFIX。

在我們這個過程當中，都是做日誌收集與分析。收集到的記錄是各種格式，你收集進來之後要進行過濾與正規化（Normalization）。正規化就是把格式完全不一樣的日誌，轉換成統一的欄位架構，正規化完成之後依照時間軸展現出來。這個東西就可以使用 Graylog 或 ELK 這類專業日誌分析平臺。

這種工具很多，要不要讓大家去收集一下？派一個回家作業給你們寫。請收集日誌分析相關的專題工具或配套軟體。我先講幾個：前兩天看到的 LibreNMS、Graylog、還有 Linux 社群常討論的 ELK Stack。重要的先提完。

## 🛠️ 開源日誌分析與網路掃描工具庫（Nmap、Wireshark、VLog）實務專題

**【授課講師】**：還有捆綁各種網路掃描工具，例如 Nmap 及其擴充腳本引擎 NSE（Nmap Scripting Engine）。還有封包收集工具 Wireshark、NetFlow 分析器。大家想一下還有哪些開源軟體？這幾樣東西在搭建開源 SIEM 時最常見。

另外像 Scapy，Scapy 現在非常熱門，可以用 Python 自由組裝與解析封包。我腦袋中還有兩套，不過先留給你們去找。

這裡我跟大家稍微提醒，我們系統裡面有 Alert（警告事件）的關聯分析規則。這可以監控目前網路與系統的活動情況。它通常屬於規則引擎，可以用邏輯條件來定義，比如由資安人員自行撰寫規則，或是匯入威脅情報（Threat Intelligence）的偵測規則，利用這些規則把異常活動呈現在儀表板上。

比如說現在有多少封包流入？有多少封包流出？把威脅情報餵給系統，讓它判斷連線來源是否為惡意 IP、目前面臨的威脅層級為何。

甚至你可以看到系統記錄中有人正在嘗試暴力破解帳號密碼，或者試圖輸入特殊的 SQL Injection、弱點利用 Payload。

但是這有可能是什麼情況？有可能是誤報（False Positive）發生！為什麼？因為有人忘記密碼。忘記密碼會一直重試，對不對？覺得應該是這個密碼，試了不對又換另一個，試來試去。

然後你平臺上的警報器就會響個不停！董事長早上一進辦公室，可能還沒吃早餐，就在那邊輸入帳號密碼，結果一直輸錯。叫秘書來幫忙輸密碼，兩個人在那邊又試了十幾二十次。

然後 SOC 值班人員就很緊張地跑過來：「報告長官，有人在嘗試暴力破解您的帳號！」董事長坐在位子上也很尷尬，為什麼？因為是他自己忘記密碼！所以這裡就要注意誤報（False Positive，假陽性）與漏報（False Negative，假陰性）的問題。

好，那當然如果你發現確實有駭客入侵活動，很明顯在進行，那你肯定要採取應變措施，先把這部機器做網路隔離。

我見過一個最厲害的網管，他發現某部機器有被入侵的跡象，駭客正在活動。他怎麼處理？他把攻擊者進來的連線路徑動態隔離，駭客一直嘗試攻擊，網管把這台機器切換到隔離的 VLAN，調整網路設定，然後故意在裡面收集駭客進來活動時的所有攻擊資料！

故意放著喔！我問他：「你這樣做會不會太冒險？」他說不會，目標就是收集駭客的攻擊手法。感覺就像是把那台主機當成了 Honeypot（蜜罐）或 Honeynet（蜜網）一樣。駭客正忙著攻擊，根本不知道自己已經被引導到受控環境裡了。等他好不容易打穿系統，才發現機器裡面什麼機密都沒有，才知道自己其實掉進了蜜罐裡。

這是我見過最有趣的一個維運網管人員，因為公司沒編預算給他建專屬蜜罐系統，他就用這種方式隨機應變。

好，那當然在這些監控過程當中，你一定要產出報告（Reports）。需要做管理紀錄、合規稽核報表，甚至要提供給主管機關或外部稽核單位查核。

另外，這些日誌記錄統統都要封存歸檔（Archive）。把資料匯出，備份存檔到 NAS 或 SAN 儲存設備上面。

我問各位一件事情：**【授課講師】**：一般我們的資安記錄檔要保留多久？

**【學員 A】**：兩年！

**【學員 B】**：七年！

**【授課講師】**：我講了，會計財務記錄才依法要保留七年。那網路資安記錄要保留多久？

**【學員】**：三個月？

**【授課講師】**：三個月太短了。

**【學員】**：一年？

**【授課講師】**：一年太久，通常建議至少保留半年到一年。

為什麼保留半年？依照 NIST SP 800-92 等電腦日誌管理標準建議，保留半年以上是標準規範。為什麼要保留到半年？因為有時候我們要追蹤 APT 進階持續性威脅攻擊事件時，駭客可能在兩三個月之前就已經植入後門潛伏了。

有的駭客非常有耐心，可以在系統裡面潛伏半年甚至一年不動。潛伏太久如果完全沒活動，可能是駭客忘記了，或是覺得這套系統沒有利用價值。但大部分駭客把後門植入伺服器後，大概在三到六個月之內就會開始發動實質攻擊。

所以我才跟各位講，日誌儲存空間大概至少要準備半年的容量。你說為什麼不保留十年？各位同學，儲存設備硬碟容量是要花錢買的，機房供電與伺服器運作也都是維運成本。

好，這些資安監控與日誌保存的重點大家要特別注意。我們先稍微休息十分鐘，休息一下之後我們再繼續。
