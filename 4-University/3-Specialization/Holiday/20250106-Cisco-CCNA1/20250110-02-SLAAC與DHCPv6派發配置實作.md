## 🔑 重點提要 (Key Takeaways)

1. **SLAAC 核心機制**：用戶端完全不需要 DHCP 伺服器即可依據路由器 RA 派送的 Prefix（前綴）自動組合出 IPv6 位址。
2. **Stateless DHCPv6 互補價值**：SLAAC 早期無法派發 DNS 伺服器位址，透過設定 RA 的 Other Configuration Flag (O-flag)，指引用戶端向 DHCPv6 索取 DNS 與網域名稱。

## 📡 IPv6 SLAAC 無狀態配置 vs. DHCPv6 派發機制與 ICMPv6 協定對照表

| 定址派發模式 | 核心位址生成與伺服器角色 | 傳輸協定與控制旗標（RA Flags） | 優缺點與企業網路部署考量 |
| :--- | :--- | :--- | :--- |
| **SLAAC 無狀態自動設定（Stateless）** | 終端透過 ICMPv6 路由器通告（RA）獲取 `/64` 網路前綴，主機自行透過 EUI-64 或隨機亂數生成後 64 位元 Interface ID | 路由器開啟 `ipv6 unicast-routing`；旗標為 $M=0, O=0$；主機無需任何集中式 DHCP 伺服器記錄租約 | 部署極簡且無伺服器單點故障風險；早期缺點為無法派發 DNS 伺服器 IP，現代多搭配 RDNSS 擴充協定 |
| **Stateless DHCPv6（無狀態輔助）** | 終端位址仍由 SLAAC 自行生成，但透過輕量 DHCPv6 伺服器獲取全網通用參數（如 DNS 伺服器與網域名稱 Domain Name） | 路由器 RA 封包設定 $M=0, O=1$（Other Configuration Flag 被啟動）；告知終端向 DHCPv6 詢問其他設定 | 兼具 SLAAC 之高速免維護性與 DHCP 集中管理 DNS 之彈性，為多數企業園區網路標準配置 |
| **Stateful DHCPv6（有狀態全代管）** | 仿照傳統 IPv4 DHCP 模式，由 DHCPv6 伺服器全權掌控位址派發池、記錄客戶端 DUID 並管理租約期滿回收 | 路由器 RA 封包設定 $M=1$（Managed Address Configuration Flag 被啟動）；終端忽略 RA 前綴，直接向伺服器索取 IP | 便於企業網管人員嚴格審計內部每台裝置之 IP 綁定紀錄，但伺服器維運複雜度與備援要求較高 |
