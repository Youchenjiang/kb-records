## 🔬 技術精華與核心考點解析

### TCP 與 UDP 協定核心特性對比

- TCP：提供可靠傳輸、循序編號、重傳機制（Retransmission）、壅塞控制與流量控制（Flow Control），適用於 HTTP/HTTPS、SSH、FTP、SMTP。
- UDP：無連線、不保證送達、無封包重組、開銷極小（標頭僅 8 位元組），適用於 DNS 查詢、DHCP、TFTP、VoIP 及即時串流。

### TCP 連線管理機制

- 連線建立：SYN -> SYN+ACK -> ACK（三次交握）。
- 連線終止：FIN -> ACK -> FIN -> ACK（四次揮手）。
- 滑動視窗（Sliding Window）：發送端在收到 ACK 前能連續發送的資料量，依據接收端緩衝區動態調整以防溢位。

## 💡 關鍵總結與考試應對重點

1. **考試常考：DNS 查詢使用 UDP 53，但 DNS 區域傳送（Zone Transfer）使用 TCP 53。**
1. **考試重點：TCP 標頭長度為 20-60 位元組，UDP 標頭固定為 8 位元組。**

## 🤝 TCP 三方交握、UDP 輕量傳輸與埠號多工分流對照表

| 傳輸層協定特性 | 傳輸控制協定（TCP, Transmission Control Protocol） | 使用者資料包協定（UDP, User Datagram Protocol） | 埠號多工分流與防火牆規則應用 |
| :--- | :--- | :--- | :--- |
| **連線導向 vs. 非連線導向** | 連線導向（Connection-Oriented）：資料傳輸前必須先經過**三方交握（SYN $\to$ SYN-ACK $\to$ ACK）**建立虛擬電路 | 非連線導向（Connectionless）：無交握機制，應用層資料即時封裝後直接投遞至網路層發送 | 知名埠號（Well-Known Ports, 0-1023）由 IANA 指派給伺服器服務（如 HTTP 80、HTTPS 443、DNS 53） |
| **可靠性保證機制** | 具備序號（Sequence Number）、確認應答（ACK）、逾時重傳（Retransmission）與流量滑動視窗控制（Flow Control） | 盡力而為（Best-Effort Delivery）：不保證封包送達、不保證順序、無重傳機制，封包遺失由應用層自行決定是否容忍 | 動態暫時埠號（Ephemeral Ports, 49152-65535）由客戶端作業系統隨機分配作為來源埠 |
| **傳輸開銷與適用應用場景** | 標頭開銷較大（最小 20 位元組），延遲較高；適用於**絕不容許任何位元遺失**之關鍵傳輸（網頁瀏覽、檔案傳輸 FTP、電子郵件 SMTP） | 標頭開銷極小（僅 8 位元組），傳輸延遲極低；適用於**重視即時性高於少許掉包**之串流（線上視訊、VoIP 語音通話、即時多人連線遊戲） | 防火牆狀態檢視（Stateful Inspection）：追蹤 TCP 連線狀態旗標（SYN/ESTABLISHED/FIN），自動允許外發連線之合規回程流量 |
