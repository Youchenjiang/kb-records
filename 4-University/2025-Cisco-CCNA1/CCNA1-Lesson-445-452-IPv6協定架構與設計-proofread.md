## 🎯 一、IPv6 誕生背景：從 32 位元到 128 位元與全局唯一性

儘管 IPv6 目前在全面普及上還沒有達到 100%，但它內部蘊含了非常多優異的設計理念與技術架構。事實上，它許多創新的設計與機制後來也被回推借用到 IPv4 環境中。IPv6 不僅僅是把位址空間從原本的 32-bit 擴充到 128-bit（位元長度整整 4 倍大，空間達到 $2^{128}$ 的天文數字），支援全球位址唯一性；更藉由這個世代交替的契機，徹底改良了許多 IPv4 長期為人詬病的架構缺陷。

我們後續會有兩個實驗 Lab 來進行實作驗證。首先介紹 IPv6 的位址空間：從 IPv4 的 32 位元（4 個 Bytes，大約 42 億多個位址）一口氣擴充到 128 位元（16 個 Bytes）。現行的 IPv4 其實在十幾年前甚至更早就已經分配告罄、不敷使用。要不是有 NAT（網路位址轉譯）、Subnetting（子網切分）與 CIDR（無類別網域間路由）等技術力挽狂瀾，IPv4 早在幾十年前就癱瘓了。從某個角度來說，NAT 正是阻礙 IPv6 迅速普及的「頭號功臣」，因為 NAT 解決了公有 IP 匱乏的燃眉之急，使得 IPv4 得以延壽續命至今。

二的 128 次方是一個無法想像的天文數字，其設計願景是讓地球上的每一顆沙子、每一件物品都能配發專屬的公開 IP。物聯網時代連冰箱裡的高麗菜都能配發 IP 位址直接 Ping 得通，位址空間絕對充裕。

回顧 IP 位址演進的時間線：IPv4 是在 RFC 791（1981 年）正式確立。我當年正好趕上那波赴美留學潮，當時美國大學非常歡迎各系所學生投入資訊科學領域，不論念社會系、中文系還是歷史系都不受限制，因為各界認定電腦與網路是各行各業必備的通用工具。到了千禧年前後，TCP/IP 正式擊敗各家廠商的私有網路通訊協定，成為全球統一的骨幹標準。

然而，大約十年前全球最後一段可分配的 IPv4 位址塊就已經正式發放完畢。Subnetting 解決了網段切割，NAT 實現了多私有主機共享少數公網 IP，CIDR 則有效濃縮匯聚路由表，避免全球路由表過度膨脹。

IETF 早就預見 IPv4 耗盡的必然命運，因此很早就提出 IPv6 RFC 規範。有些人好奇為什麼沒有 IPv5？其實當年 IPv5 曾被提出作為實驗性串流協定，但很快被評估為不可行而終止，直接由 IPv6 躍居正宗繼承者。全球 IP 位址由最高主管機構 IANA（網際網路號碼分配局）統一管理，授權給各大洲的區域註冊機構（例如北美美洲區的 ARIN、亞太區的 APNIC 等），再分配給各國電信業者（ISP），最後交給企業與終端客戶。北美 ARIN 的 IPv4 位址早在 2015 年就全部分配告罄。

既然 IPv4 早已耗盡，為何 IPv6 遲遲無法全面淘汰取代 IPv4？關鍵原因在於**缺乏殺手級應用（Killer App）**！對應用程式開發者而言，若公有 IP 不足可以用 NAT 與反向代理輕鬆解決，就沒有強大動機大費周折改用長串的 IPv6 開發。

事實上，全球各家電信運營商的骨幹基礎架構（Infrastructure）早就全面就緒。電信商骨幹路由器早已全面支援 **Dual-Stack（雙堆疊）**架構，同時跑 IPv4 與 IPv6 雙協定堆疊路由，連 IPv6 DNS（AAAA 紀錄）也早就配置完成，隨時虛位以待。只缺東風——也就是缺乏非 IPv6 不可的原生殺手級應用。原本各界預期智慧型手機與物聯網（IoT）大爆發會強制推動 IPv6，但現行各類工程技術仍能在 IPv4 下應付自如。我曾詢問當年積極推動 IPv6 研討會的大學校園學者，為什麼後來熱度降溫？大家苦笑說，因為 IPv6 那一長串 128 位元的十六進位位址實在是「又臭又長、既難抄又難背」，工程師光是手動除錯配置就感到頭痛。

## 📐 二、固定標頭（Header）結構改良與硬體線速轉發

我們深入探討 IPv6 在表頭（Header）架構上的革命性改良。IPv6 記取了 IPv4 的慘痛教訓，首要任務就是簡化表頭結構。

在 IPv4 表頭中，設計了許多 Option（選項）欄位。在 IPv4 中，就算完全不使用選項，該欄位空間依然存在；這給予駭客可乘之機，能刻意塞入異常碎片或惡意填充（例如利用 Fragment Offset 發動小封包重組攻擊，讓伺服器 CPU 疲於重組而當機耗盡）。IPv6 徹底揚棄了這種不良設計，**基本表頭完全取消可選欄位，將長度固定為 40 個 Bytes**！若需要額外功能（如分段、加密安全認證），改採「**Extension Header（擴充標頭）**」，透過 `Next Header` 指針像火車車廂一樣串接掛載，讓選項真正成為選配。

此外，IPv6 對欄位名稱進行了精準正名：
1. **Traffic Class**：取代 IPv4 原本的 Type of Service（ToS），直接以封包分類（Class of Service，如航空艙等劃分 QoS 等級）正名；
2. **Hop Limit（跳數限制）**：取代 IPv4 的 TTL（Time To Live）。TTL 常讓人誤以為與時間秒數有關，事實上它本質就是每跨越一跳 Router 就減 1 的 Hop Count，因此在 IPv6 中精確正名為 Hop Limit；
3. **Payload Length（有效載荷長度）**：取代 IPv4 的 Total Length。原本的 Total Length 易被誤解為整體封包長度，IPv6 正名為 Payload Length，專門記錄基本 40-Byte 表頭之後所帶資料（含擴充標頭）的長度。

IPv6 保留 IPv4 原始名稱的欄位僅有三個：**Version（版本）**、**Source Address（來源位址）**與**Destination Address（目的位址）**。唯一全新增加的欄位是 20-bit 的 **Flow Label（流量標籤）**。傳統路由器在識別特定資料流時，必須費力解析檢查五元組（來源 IP、目的 IP、協定、來源 Port、目的 Port），消耗大量運算資源；而 Flow Label 允許路由器直接靠單一標籤快速識別特定的即時多媒體資料流，大幅加速轉發效率。

固定 40 個 Bytes 的表頭長度至關重要！因為固定長度非常適合以 ASIC 硬體晶片進行管線化線速處理（Hardware Wire-speed Forwarding），不必再動態計算變長表頭。這個硬體導向的設計概念吸取自早期的 ATM Switch（非同步傳輸模式交換機，當年廣域網路技術），利用固定 Cell 長度實現高速硬體交換。

## 🌉 三、IPv4 到 IPv6 三大過渡技術：Dual-Stack（雙堆疊）、Tunneling（隧道）與 NAT64

在 IPv6 路由轉發架構中，路由轉發邏輯與 IPv4 完全相同：解封裝第二層 MAC Frame，比對第三層目的 IP 與路由表，再封裝新的第二層標頭送出。

目前業界公認的三大過渡機制包括：
1. **Dual-Stack（雙堆疊，業界首選）**：設備介面同時配置 IPv4 與 IPv6 雙位址，網路節點同時運行 IPv4 與 IPv6 雙路由表。封包是 IPv4 就查 IPv4 路由，是 IPv6 就查 IPv6 路由。這是最穩定、最推薦的平滑過渡方案。
2. **Tunneling（隧道技術）**：當兩個分離的 IPv6 孤島（IPv6 Islands）必須跨越中間純 IPv4 的 Internet 骨幹相連時，在邊界路由器上將 IPv6 封包封裝進 IPv4 封包內建立隧道穿透傳遞。
3. **NAT64 / Translation（位址轉譯）**：在純 IPv6 網段與純 IPv4 網段之間，透過 NAT64 設備進行協定與位址的相互轉譯。

在轉發效率上，IPv6 做出了一項重大變革：**IPv6 路由器不再檢查 Checksum（校驗和）**！IPv4 要求沿途每一個 Router 都要重新計算與檢查 Header Checksum；但考量現代底層光纖網路品質極高，且第二層（Ethernet CRC）與第四層（TCP/UDP）都有各自的錯誤檢查機制，IPv6 路由器徹底取消了每跳檢查碼比對，僅保留端點（End-to-End）驗證，進一步降低轉發延遲。

此外，第三層升級為 IPv6 並不影響底層第二層（MAC Address、Switch 運作維持不變），也不影響上層應用協定（HTTP/HTTPS 依然相同）。

## ✂️ 四、IPv6 地址表示法與雙冒號（::）零壓縮單次限制原則

IPv6 採用 128 位元長度，以**十六進位制（Hexadecimal）**表示。每 16 位元為一組，共分為 8 組，組與組之間以冒號（`:`）隔開（每組由 4 個十六進位字元構成，範圍從 `0000` 到 `FFFF`）。

完整的 IPv6 位址極長，認證考試必考「位址簡化規則」：
- **規則一：前導零省略（Leading Zeros Omission）**：每組十六進位數字中，「前面的零」可以省略不寫。例如 `000F` 可簡化為 `F`，`0200` 簡化為 `200`，`0000` 簡化為單一的 `0`。**特別注意：結尾的零（Trailing Zeros）絕對不可省略**！例如 `1230` 若把後方的 `0` 省略就會變成完全不同的位址。
- **規則二：連續零壓縮（Successive Zeros Compression with `::`）**：由多組連續全為零的欄位（如 `:0000:0000:0000:`），可以使用單一的**雙冒號 `::`** 代替。**鐵律：在同一個 IPv6 位址中，雙冒號 `::` 最多只能出現一次**！若出現兩個以上的雙冒號，系統解讀時將無法判定各自還原的零數量，會直接被系統判定為無效的語法錯誤位址。

在 IPv6 位址架構中：
- 前 64 位元為 **Network Prefix（網路前綴）**，相當於 IPv4 的網路位元；
- 後 64 位元為 **Interface ID（介面識別碼）**，相當於 IPv4 的主機位元（Host Bits）。
IPv6 完全取消了傳統十進位的子網遮罩（如 `255.255.255.0`），一律統一採用 **前綴斜線標記法（Prefix Length，如 `/64`）**。

在配套核心協定方面：
1. **動態路由協定**：IPv4 常用的 OSPFv2 僅支援 IPv4；若要在雙堆疊環境中繞送 IPv6，必須改跑 **OSPFv3**。
2. **ICMPv6**：在 IPv6 架構中扮演極其關鍵的角色，功能大幅擴展。
3. **NDP（Neighbor Discovery Protocol，鄰居探索協定）**：徹底取代了傳統的 ARP 廣播協定！在 IPv6 世界中完全沒有 ARP，第三層 IPv6 位址與第二層 MAC 位址的解析與鄰居狀態維護，全權由基於 ICMPv6 多播的 NDP 負責。
