## 🎯 一、IPv6 地址簡化兩大黃金規則與試題練習

我已經把練習題分享在學員群組，大家可以參考對照。我們很快來逐題討論：

根據剛剛介紹的 IPv6 位址簡化兩大核心原則：
1. **前導零省略（Leading Zeros Omission）**：冒號與冒號之間的 4 碼十六進位中，只要是「前面的零」都可以省略；但「後面的零」絕對不能省略。
2. **連續零壓縮（Successive Zeros Compression with `::`）**：連續全為零的組別可以用雙冒號 `::` 代替，但**在同一個位址中最多只能出現一次**！

在 Cisco 認證考試中，IPv6 位址簡化大約會出 3 到 5 題，屬於送分題，大家一定要全對、絕不能失分！

在各題範例中：
- 例如遇到連續全零欄位，直接壓縮為雙冒號 `::`；
- 前面的零如 `0006` 直接簡化為 `6`；
- 但後面的零如 `1000` 絕對不能省略！
- 若位址中已使用了一次 `::`，其他後續出現的全零組別就只能寫成單一的 `0`，絕對不能在同一個位址中寫出兩個雙冒號。

以 `FE80::` 開頭的位址為例，這在 IPv6 中是極其特殊的 **Link-Local Address（連結本地位址）**，也是認證考試的重點核心！只要任何作業系統或網路介面勾選啟用了 IPv6，系統就會自動為該網路卡產生一個 `FE80::` 開頭的 Link-Local 位址。各位在自己的 Windows 電腦開啟命令提示字元輸入 `ipconfig`，就能立刻看到以 `FE80::` 開頭的位址。

Link-Local 位址在 IPv6 中地位無可替代：
- 它是動態路由協定（如 OSPFv3）**建立鄰居關係（Neighbor Adjacency）的專用位址**。即使環境中尚未規劃全域 IPv6 路由，只要有 Link-Local 就能直接完成鄰接協商。
- 為什麼叫 Link-Local？因為它僅在當前實體鏈路（同一網段）內有效，路由器絕不轉發跨網段的 Link-Local 流量。別的網段完全不知道這個位址，因此非常安全。
- 它同時會**自動成為路由表中的 Next-Hop（下一跳）位址**，這也是 IPv4 所沒有的重大創新。

在網段劃分練習中，以 `/64` 為例，代表前 64 位元為網路前綴（Prefix）。每組 16 位元，因此前 4 組（即前 4 個冒號區段）即為網路前綴，後 64 位元則為 Interface ID。

在 IPv6 世界中，介面定址極具彈性：**單一實體網路卡或路由器介面，原生支援配置多個 IP 位址**！無論是同網段還是跨網段的多個位址，皆可直接綁定在同一介面上，完全不需像 IPv4 那樣額外宣告宣告 `secondary` 參數。

## 📡 二、廢除廣播機制與 Multicast（群播）替代方案

IPv6 的另一項革命性架構改變，就是**徹底廢除了 Broadcast（廣播）機制**！廣播在 IPv4 中會對全網段所有主機無差別打擾，極度浪費頻寬與主機 CPU 處理能力。

在 IPv6 中，若需要達成一對多的傳播需求，全面改採 **Multicast（群播）** 與 **Anycast（任播）**：
- **Unicast（單播）**：一對一通訊；
- **Multicast（群播）**：一對多通訊。接收端主機必須預先主動加入特定的群播群組，才會接收該群組的封包。

群播技術有兩大核心優勢：
1. **大幅節省網路頻寬**：若有 100 個接收者，若用單播傳送，伺服器必須個別封裝發送 100 份封包（因為每個目的 IP 皆不同）；而若改用群播，伺服器只需發送 1 份封包至特定群播位址，沿途交換機與路由器會自動在分岔路徑複製轉發，大幅減輕伺服器發送端與骨幹頻寬負擔。
2. **保證資料同時到達（Zero Latency Jitter）**：單播依序發送必定產生時間差，唯有群播能讓所有接收端同時接收資料。例如台灣證券交易所（證交所）、期貨交易所（期交所）的金融報價系統，極度依賴群播技術，確保所有券商交易員在同一個微秒內同時接收最新報價行情。

在 IPv4 中，群播僅屬於選配技術（企業內部少有配置，多半靠單播傳輸）；但在 IPv6 中，**Multicast 是不可或缺的絕對核心機制**！IPv6 的底層協定（如 NDP、DHCPv6、路由協定）大量且強制採用群播運作。

此外，IPv6 正式引進了全新定址模式：**Anycast（任播）**。
Anycast 的設計精髓在於：**在多台不同網路裝置的多個介面上，刻意配置完全相同的 IP 位址**！
這樣做不會造成位址衝突嗎？完全不會！因為 Anycast 利用路由協定最短路徑原則，讓終端使用者自動連向「距離自己網路拓撲最近（Nearest）」的那一台伺服器或閘道。

**Default Gateway（預設閘道）**就是 Anycast 的最佳實務典範：大型企業可在不同機房部署多台 Default Gateway，全數配置同一個 Anycast IP。終端 PC 會就近尋找網路跳數最近的 Gateway 進行繞送，平時達成天然的流量負載平衡（Load Balancing）；一旦離自己最近的 Gateway 發生故障斷線，動態路由會自動將流量切換指引至次近的備用 Gateway，兼具高可用性與容錯備援（Fault Tolerance）。

## 🌐 三、Global Unicast vs. Unique Local：IPv6 定址哲學

IPv6 定址架構主要分為三大範疇：
1. **Link-Local Address（連結本地位址）**：固定為 `FE80::/10` 開頭，由系統自動產生，僅限本地鏈路通訊，不可跨路由器路由。
2. **Global Unicast Address（全域單播位址，GUA）**：相當於 IPv4 的公有 IP。目前 IANA 僅開放 **`2000::/3`** 這個前綴區段（佔全體位址空間的八分之一）供全球各機構申請發放，其餘龐大空間仍全數保留。光是 `2000::/3` 這八分之一的位址量，就已徹底滿足全球所有行動裝置與物聯網裝置的永久需求。
3. **Unique Local Address（唯一本地位址，ULA）**：固定為 **`FC00::/7`**（實務上為 `FD00::/8`）開頭。這是為滿足傳統企業內部網路（Intranet）私有網段隔離需求而保留，相當於 IPv4 的 RFC 1918 私有位址（Private IP），僅限企業內部互通，禁止路由至公共網際網路。

在特殊本機位址方面：
- **Loopback 位址**：寫作 **`::1`**（等同於 IPv4 的 `127.0.0.1`）。用來 Ping 測試本機作業系統的 TCP/IP 協定堆疊運作是否健全。
- **未指定位址（Unspecified Address）**：寫作 **`::`**（128 位元全為 0，等同於 IPv4 的 `0.0.0.0`）。用於主機尚未取得 IP（如發出 DHCPv6 或 SLAAC 請求）時作為來源 IP 使用。
- **預設路由（Default Route）**：寫作 **`::/0`**（等同於 IPv4 的 `0.0.0.0/0`）。

## 🔗 四、Link-Local 位址生成與 EUI-64（FFFE 插入與位元翻轉）實務

在生成 Link-Local 位址的 Interface ID（後 64 位元）時，主要有兩種機制：
1. **隨機生成（Randomized Generation）**：例如 Windows 用戶端作業系統預設採用隨機演算法生成後 64 位元，以維護隱私安全；
2. **EUI-64（Extended Unique Identifier 64）標準規則**：思科網路設備與許多 Linux 系統預設採用此規則，直接由介面的 48-bit MAC Address 轉換生成。

**認證考試必考 EUI-64 轉換三大步驟**：
1. **拆分 MAC 位址**：將 48 位元 MAC 位址切分為前半段 24 位元（OUI）與後半段 24 位元；
2. **插入 `FFFE`**：在前後兩段正中間插入固定的 16 位元十六進位值 **`FFFE`**，使位元數擴展至 64 位元；
3. **第 7 位元翻轉（Invert / Flip the 7th Bit）**：將第 1 個 Byte 中的第 7 個 Bit（即 Universal/Local 位元）進行反轉（原本是 0 則改為 1，原本是 1 則改為 0）。例如 MAC 開頭若是 `00`（二進位 `0000 0000`），第 7 個 bit 翻轉後變成 `0000 0010`，十六進位即變為 `02`。

在子網切分（Subnetting）實務中：
- 終端使用者的 Interface ID 固定為後 64 位元，維持不動；
- 電信業者分配給企業的 Global Routing Prefix 通常為 `/48`；
- 企業網管可利用第 48 位元至第 64 位元之間的 **16 個位元作為 Subnet ID**！$2^{16} = 65,536$，單一企業即可劃分出 65,536 個獨立子網，每個子網皆具備 $2^{64}$ 個主機位址，徹底免除 IPv4 繁複的借位計算。

最後探討 IPv6 最強大的隨插即用技術——**SLAAC（Stateless Address Autoconfiguration，無狀態位址自動配置）**：
設備接上網路線時，不需依賴 DHCP 伺服器，直接透過 **NDP（鄰居探索協定）** 的路由器通告（Router Advertisement, RA）取得網段 Prefix（前 64 位元）與預設閘道位址；設備本機再依據 EUI-64 規則自動生成後 64 位元 Interface ID，兩者拼接即自動形成合法完整的 128 位元 IPv6 位址，真正實現 **Plug and Play（隨插即用）**。
