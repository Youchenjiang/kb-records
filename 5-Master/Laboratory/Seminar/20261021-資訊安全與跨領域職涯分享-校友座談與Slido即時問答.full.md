## 🎮 職涯修煉如楓之谷轉職：初心者、劍士、槍騎兵到龍騎士的技能樹開展

**【主持人】**：各位同學大家午安，今天非常高興邀請到我們非常優秀的學長回母校，跟大家分享他在資訊安全領域的實戰歷練、跨領域轉職經驗與職涯規劃。現場我們也開啟了 Slido 匿名提問系統，大家如果有任何害羞不敢當面問的問題，都可以隨時投到 Slido 上。讓我們以熱烈掌聲歡迎學長！

**【校友講者】**：謝謝老師、主持人與各位學弟妹。今天回到母校跟大家分享，我希望這場分享不是死板板地講教條，而是能真正解答大家心目中對研究所、求職或學習方向的迷惘。在開始之前，大家小時候應該都有玩過《楓之谷》（MapleStory）這款經典線上遊戲吧？

**【校友講者】**：在《楓之谷》的世界裡，所有人剛登入遊戲時都是「初心者」（Beginner）。大家在初心者時期拿著小木劍打嫩寶、慢慢摸索世界；接著升到十等，你必須做出人生的第一個重要抉擇——「轉職」。你可能選擇成為劍士、法師、弓箭手或盜賊；轉職之後開始打怪升等、配點技能、購買裝備，升到三十等再進行二轉，例如劍士可以二轉成狂戰士、見習騎士或「槍騎兵」；升到七十等再三轉成「龍騎士」或十字軍，解鎖全螢幕龍咆哮與終極戰力。

**【校友講者】**：我回顧自己一路從大學、研究所到進入產業界做資安的過程，發現這跟《楓之谷》的升等轉職簡直一模一樣！一開始大家進入大學資工或資管系，大家都是技術初心者。我高中在南部唸書，那時候根本沒有提早學程式，純粹是因為喜歡打電動，填志願時覺得「念這個好像能跟電玩相關，而且父母也說出路不錯」就進來了。

**【校友講者】**：大一剛進來時，在黑底白字的終端機上印三角形、算質數，覺得超級枯燥無聊，完全不知道自己在搞什麼。直到後來接觸到 CTF（Capture The Flag）資訊安全競賽，看到各路黑客在 Binary 逆向工程、Web 滲透、密碼學與系統漏洞挖掘中各顯神通，我才發現這就像遊戲裡的各種職業分支：有人專攻 Web 漏洞就像靈活的盜賊，有人專攻逆向與 Pwn 就如同正面硬剛的劍士。

**【校友講者】**：我那時候選了 Binary 逆向與記憶體破壞這條路，就像轉職成了「劍士 Hunter」。這條路非常吃底層組合語言、作業系統核心與記憶體佈局。經過幾年的鑽研與國內外打靶打比賽，技術慢慢純熟，晉升到「槍騎兵」；最後在職場上確定方向，專注於事件應變（Incident Response）、威脅狩獵與災難救援，真正成為防護企業數位資產的「龍騎士」。

## ⚔️ CTF 戰隊實戰與學習瓶頸突破：從 Binary 逆向到國際頂級競賽

**【校友講者】**：在學習資安與打 CTF 的過程中，大家一定會遇到極大的挫折與瓶頸期。很多學弟妹常問我：「學長，我解題卡關好幾天解不出來，我是不是不適合走資安？」我想告訴大家：**卡關是 100% 的常態！**

**【校友講者】**：資安領域的知識迭代速度非常驚人。當你剛學會一個攻擊手法（例如 Buffer Overflow 覆寫 Return Address），作業系統立刻推出 ASLR、DEP/NX、Canary 保護機制；當你學會 ROP（Return-Oriented Programming），編譯器又推出 CFI（Control Flow Integrity）。打 CTF 最珍貴的資產不是拿到多少分數，而是鍛鍊你的「自學突破能力」與「心態韌性」。

**【校友講者】**：即使你在比賽中沒有解開題目、沒有拿到好名次，但只要賽後仔細研讀別人的 Writeup、弄懂出題者的漏洞設計原理，你就已經掌握了新的技術。另外，資安絕對不是孤狼作戰，一個成功的團隊必須截長補短。在我們戰隊裡，有隊友程式碼識讀能力極強、能在一萬行原始碼中一眼抓出邏輯缺陷；有人擅長逆向動態除錯；有人擅長自動化腳本編寫。互相討論、承認自己的盲點，是進步最快的方式。

## 🛡️ 紅隊滲透與藍隊防禦：實務合規界線、漏洞挖掘與企業資安需求

**【校友講者】**：接著我想聊聊企業實務上的「紅隊滲透測試（Red Teaming）」與「藍隊防禦（Blue Teaming）」。很多同學剛接觸資安時，都覺得當紅隊黑客非常帥氣、拿著工具到處打靶打點很過癮。

**【校友講者】**：但在真實產業界，紅隊滲透測試有著極其嚴格的「法律合規邊界與服務合約（Rules of Engagement, RoE）」。在進場之前，你必須跟企業客戶白紙黑字簽訂嚴格的授權合約：規範測試時間窗口、允許滲透的網段與 IP 範圍、禁止碰觸的生產環境核心資料庫（避免伺服器當機影響客戶營業）。在合法授權之外做任何未授權探測，都是違法犯罪行為，這條紅線絕對不能踩。

**【校友講者】**：而另一方面，「藍隊防守與鑑識」的需求在當前企業界是極為龐大且缺乏高素質人才的。企業遭遇勒索軟體加密、APT 組織橫向移動侵入時，需要的是能迅速釐清入侵途徑、進行記憶體鑑識、修補漏洞並重建安全架構的專案專家。這類防守與鑑識能力，往往比單純跑工具掃漏洞具有更高的職場護城河。

## 💬 Slido 即時問答對焦：突破 AI 提問限制、課業競賽平衡與求職心態

**【主持人】**：好，現場同學非常踴躍，Slido 上面已經累積了非常多高票問題。我們挑選幾題最重要的請學長解答。

**【提問研究生】**：學長好，Slido 上面最高票的問題是：「最近用 ChatGPT 或其他大語言模型問資安或程式碼漏洞問題時，AI 常常會跳出警告說違反安全政策拒絕回答，請問學長在實務上都怎麼跟 AI 提問與互動？」

**【校友講者】**：這題問得非常棒！這正是現在大家都會遇到的情況。AI 為什麼會拒絕回答？因為各大商用模型（OpenAI、Anthropic、Google）都有嚴格的 Safety Guardrails（安全護欄）。如果你直接問它：「請幫我駭進某某網站」或「請幫我寫一個能偷密碼的木馬病毒」，模型偵測到強烈的惡意意圖，一定會觸發安全政策把你的 Prompt 打下來。

**【校友講者】**：要怎麼合法且有效地讓 AI 成為你的研究助手？**關鍵在於「情境包裝」與「拆解問題層次」！**
第一，你可以將問題包裝成合法的教育與競賽情境，例如：「我目前正在參加資安教育訓練/解 CTF 題目，遇到了這一段 C 語言記憶體複製程式碼，請幫我分析這段程式碼在邊界處理上有沒有潛在的邏輯缺陷或未預期行為？」
第二，更專業的做法是「不要直接問漏洞，而是問底層機制」！例如不要問它「怎麼利用這個漏洞攻擊」，而是問它「在 Linux x86-64 架構下，當呼叫 `malloc` 遇到特定 chunk 大小變動時，glibc 記憶體分配器內部的 fastbin 與 unsorted bin 是如何進行鏈表重構的？」當你把問題深入到底層系統機制與程式語言特性時，AI 不僅不會拒絕，還能提供非常精闢的技術解析。

**【提問研究生】**：第二個高票問題是：「碩士班期間如果花很多時間打資安競賽或研究底層漏洞，會不會導致實驗室研究與畢業論文進度落後？學長當初是怎麼平衡競賽與學業的？」

**【校友講者】**：這確實是很多研究生的痛點。我的經驗是：**把競賽題目與你的碩士論文主題進行「深度綁定」！**
如果你是資安實驗室，你完全可以把你在競賽中遇到最前沿的漏洞樣態、利用手法或防禦瓶頸，轉化為你的學術論文研究題目。例如從競賽中的 RAG 知識庫投毒、核心漏洞修補，延伸出系統化的防禦架構。這樣你在打比賽鍛鍊實戰能力的同時，其實就是在為你的論文蒐集實證數據，讓競賽與論文相輔相成，而不是彼此排斥。

**【提問研究生】**：最後一個問題是關於求職面試：「非純資工背景或沒有大廠實習經驗的同學，在應徵一線資安工程師職位時，履歷上該如何展現自己的優勢？」

**【校友講者】**：在資安與軟體工程領域，面試官最看重的從來不是你的科系名稱，而是你的「技術實證與解決問題的能力（Proof of Work）」。一份平庸的履歷寫滿修課成績，但一份亮眼的履歷會直接附上你的 GitHub 開源專案、公開的 CTF Writeup 技術部落格、或你在各大漏洞賞金平台（Bug Bounty）合規回報的 CVE 漏洞致謝。這些可被公開檢驗的成果，遠比任何名校文憑或修課名單更能證明你的實力。

**【校友講者】**：希望大家不要給自己設限，從初心者開始一步一腳印升等轉職，終究能找到屬於自己的專業天空。謝謝大家！

**【主持人】**：非常感謝學長今天毫無保留的精彩分享與解答！我們今天的講座就到這邊圓滿結束，謝謝學長！
