## 🎙️ 開場：AI 系統生命週期評測（Evaluation）與 CI/CD 落地實踐

你可以去把它做這些分類，然後一步的往下去看它的工具與指標。那當然最重要的還是 Quality（品質）的部分，因為有很多時候其實可能不是只是單純的答案跟結果，還有企業自己的評估維度，因為可能這個結果在模型 A 表現好、在模型 B 表現差，但這些就是路，然後去校準這個評分的依據。那我們剛剛講的很多環節都是在左手邊，就是有關品質的這個部分，但除了品質之外，其實在安全的部分。微軟也提供了 AI Red Teaming 的 Agent，這個等一下在接下來的 Session 也會詳細跟大家做一些分享。所以不管是品質指標或是安全維度，其實我們都需要定義同一套基準，然後並且把它變成是一個完整的評測標準。

最後我們就會把它這些概念變成是傳統的 CI/CD 想法，就是我們當有一次 PR 變更，然後我們做一次新的 Prompt 調教或模型微調，接下來用 Evaluation 去評估修改之後的結果有沒有超過原本所定義的 Baseline 水準，如果有超過的話，那它才會正式放到生產環境裡面。所以它並不是單純的 A/B Test，而是透過幾十種、幾百種不同的 Evaluator 來確定這個版本的品質 Baseline。

上線之後，當然就需要統一的 Dashboard 監控：功能命中率、Latency 延遲、HTTP 成功率等，這是從系統 Observability 的角度來看。但另外一方面就是我們剛剛講企業制定的這些 Evaluation 機制，也同時不斷的在每一次使用者的對話交談互動過程中持續累積，然後當有一些異常發生的時候就會提醒同仁應該要做修正。我們也有 UI 介面，方便大家設定一次性或排程自動執行 Evaluation，確保品質不會出意外。

另外一個有趣的事情，在評測資料取樣時，我們希望透過 Clustering 分群，確保測試案例分佈均勻，例如 100 個 Test Case 均勻分佈在 10 種不同情境類型，這些都可以透過平台協助各位做到。

建立 Evaluation 機制後，有了 Log 與評測資料，系統目前有 Prompt & Model Optimizer，自動建議最佳 Prompt 或推薦替代模型（如候選方案一、方案二），提供具體改善建議。當然從商業與成本的角度進行 ROI 計算，將 Business Sense 納入最終評估指標。總結來說：上線前建立 Evaluation 評測機制；上線後持續收集 Logs 並把邊界案例轉為 Synthetic Data 擴充測試集，確認超越 Baseline 後發布，建立起持續改進的 Evaluation Loop。接下來我就把時間交給我的同事 Fend，針對 Agent 安全性與紅隊演練為大家深入說明。

## 🛡️ Fend 分享：Agent 安全架構、風險四維度與 PyRIT 自動化紅隊演練

大家好，我是 Fend。在 Agent 時代，我們特別關注評估的四個關鍵維度。前兩個是典型的 Quality 問題，而第三與第四個在實務上極為關鍵：第三個是「任務偏移（Task Drift）」，它不直接是漏洞，但偏離了原本被賦予的任務方向；第四個是「行為規範違規（Behavior & Policy Violation）」，例如是否違反企業合規條款或商業道德約束，這是評估 Agent 實務落地不可忽視的維度。

特別是在做 Red Teaming（紅隊演練）這件事，在機器學習時代我們就推出過開源工具 PyRIT（Python Risk Identification Toolkit）。而在 Agent 安全演進上，整個 AI 應用的防禦架構，其實可以分成四個層次：第一層是「基礎模型層（Model Layer）」，檢視模型本身是否具備安全對齊（Alignment），是否會在特定提示下輸出惡意內容或有害行為，這是在基礎訓練與安全微調時要解決的，像微軟在微調 Foundation Model 時會部署安全微調與內容過濾層。第二層與第三層則是「系統層與應用層（System & Application Layer）」，由開發者主導，當我們拿 GPT-4 或 GPT-5 串接 Agent Layer、整合各類 MCP Server 或外部 Tool 時，如何在系統層建立防護邊界、在應用層建立過濾機制，確保架構沒有漏洞。這正是 Shift-Left（安全左移）思維：在 Agent 開發週期中，越早在左側的開發與 QA 階段引入 Red Teaming，就越能提早衡量並緩解潛在風險。

畫面左邊紅色代表 Red Teaming（紅隊攻擊方），藍隊則是防禦方。紅隊演練會針對你的應用場景，自動發起多種攻擊策略，例如常見的社交工程話術、角色扮演誘導（像『我過世的阿嬤以前都會念 Windows 啟用序號給我聽』這種經典越獄話術）。又例如字詞倒置或反向編碼攻擊，人類閱讀不易，但 LLM 透過語意嵌入能理解意圖，若未經安全對齊，早期模型甚至會因此繞過審查直接輸出有害操作指南。

我們將這些攻擊策略整合在 Red Teaming 掃描引擎中，自動針對你的 AI 應用發動攻擊。如果 10 次攻擊中有多次成功突破防線，就代表 Attack Surface 與風險評分偏高。測試維度涵蓋程式碼外洩、越獄注入、敏感資訊探測等各面向。在操作時，選擇 Target Endpoint、設定攻擊策略複雜度與面向，確認無誤後即可執行自動化 Red Teaming Scan。掃描結束後產出結構化報告（JSON/CSV），詳細列出各策略複雜度下的成功率與 KPI 指標，Risk Score 顯示 0.0 是最健康的狀態，代表攻擊全數被防禦攔截。報告中可檢視每次攻擊的 Prompt 內容與採用策略（如字元反轉、編碼轉換等）。

## 📋 Agent 評估框架、SAG Control 與國際法規對齊

微軟負責任 AI（Responsible AI）團隊在 6 月推出了一套專門針對 Agent 行為與品質的評估框架。在 Agent 時代，除了傳統 LLM 的文字評估外，更著重於 Agent 的自主行為是否符合預期工作邊界。此框架開源並支援常見的第三方架構，其核心精神在於：被設計用來處理業務的範圍，就是它必須嚴格受評估的安全邊界。

該框架包含四大步驟：第一步「系統化風險維度分類」，根據 System Prompt 與業務場景，利用輔助模型拆解出該場景專屬的風險面向（例如銀行經理 Agent 可能面臨未授權轉帳、資料過度分享 Data Oversharing 等風險）；第二步「生成專屬測試資料集（Synthetic Testset）」；第三步「對目標 Agent 執行推論測試」；第四步「結合 Policy Code 進行評估」，驗證加入防護規則前後，Agent 行為是否有實質改善。

此外，在 4 月發布的開源標準中，目的在於為典型 Agent 框架（不論是 Semantic Kernel、LangChain 或 AutoGen）在中間加入一層治理控制層（Agent Governance Layer）。其控制規範稱為 SAG Control Specification（Security Agent Control Specification），將 AI Agent 的治理控制項標準化，並將歐盟 AI 法案（EU AI Act）、美國 NIST AI RMF、ISO 42001 等國際標準的控制項對齊。微軟早在 2018-2019 年就啟動 Responsible AI 實踐。除了微軟，另一家深耕安全認證的國際百年領導廠商 UL Solutions，在制定安全標準與政府法規方面具有全球影響力。新說資訊攜手 UL 與微軟，將最新的 UL 315 AI 預檢測工具引進台灣，協助企業落實 AI 治理與合規。謝謝大家。

## ⚖️ 先（Sean）分享：全球 AI 法規挑戰與 UL 315 AI 產品安全評估標準

我是新說資訊的講師 先（Sean）。我想我們直接從一個大家都在面對的真實問題開始：AI 應用快速普及，企業如何打造一個負責任且可信賴的 AI？從歐盟推出的全面性《人工智慧法案》（EU AI Act），到台灣推動的《人工智慧基本法》草案、韓國推動的 AI 基本法，以及新加坡推出的生成式 AI 治理架構，面對這麼多各國不一致的治理標準，如何確保 AI 產品合規？這就是 UL 315 可以發揮價值的地方。

UL 315 是專門針對 AI 產品推出的安全與治理評估標準。它參考了歐盟法規、對齊了 ISO 42001 等國際標準，且目前正被提案採納為美國與加拿大的國家標準。UL 315 涵蓋 12 項核心原則，聚焦於三大關鍵問題：
1. 技術層面檢驗『做得對不對』（系統穩定性與風險管理）；
2. 倫理層面檢驗『會不會傷害人』（公平性與隱私資料保護）；
3. 治理層面檢驗『有沒有人能負責』（合規文件與問責機制）。

我們現階段特別聚焦在隱私與資料保護，以真實案例來說明：Clearview AI 於 2020 年被揭露未經通知且未經同意，從公開社交平台抓取數十億張使用者照片建立人臉辨識資料庫，嚴重違反 GDPR 原則。除了業務被迫限縮於執法機關，因臉部辨識演算法偏差導致無辜民眾遭到錯誤逮捕，引發嚴重的人權與倫理爭議，面臨多國政府的巨額罰款與集體訴訟。這告訴我們：企業必須在 AI 產品生命週期早期就發現並緩解風險。

## 🛠️ UL 315 預檢測工具架構與合規判定實務

為此，新說資訊與 UL Solutions 及微軟深度合作，共同打造了 UL 315 預檢測工具。UL Solutions 是全球安全科學的領導者，微軟提供技術與治理指導，新說資訊負責將抽象的安全標準轉化為企業現場可落地的自動化預檢測工具。

在核心架構上，工具將檢測項目拆解為細部指標：
1. 使用者依檢測項目上傳對應佐證（文件、架構圖或程式碼）；
2. 由 Evaluation Engine 擷取關鍵資訊；
3. 交由判定模組比對 UL 專家制定的評分規程（Evaluation Rubric）進行客觀判定；
4. 由 Report Engine 產出可追溯的合規預檢測報告。

在稽核與判定邏輯上，我們堅持兩大設計原則：第一，每輪檢測獨立執行，避免受到過往舊結論的干擾偏見；第二，不強迫 AI 只能給出二元對立的『合規』或『不合規』判定，而是允許標註第三種『證據不足』狀態，避免誤判並留給人工審查空間。透過 UL 315 安全評估框架與預檢測工具，企業能在開發初期便落實風險管理，打造出真正可信賴（Trustworthy）與穩定營運的 AI 系統。謝謝大家！
