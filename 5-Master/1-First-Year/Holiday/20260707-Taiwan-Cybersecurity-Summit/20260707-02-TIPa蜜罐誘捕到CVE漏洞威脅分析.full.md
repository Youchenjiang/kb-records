# 🎙️ 從 TIPa 蜜罐誘捕到 AI 驅動 CTI 威脅情資分析實戰

> **【排版與校對說明】**：
> 本文件收錄資安新秀**蔡全宇（Leo）**與**資深法人資安前輩**於 InfoSec Taiwan 2026 現場聯合發表之演講逐字稿。
> 講座由淺入深，前半段由蔡全宇解析開源多蜜罐整合平台 T-Pot（TIPa）之 Docker 容器隔離、ELK 日誌管線與誘捕矩陣；後半段由曾於全國學術網路佈署 6,000 個 IP 蜜罐、日收 2 億筆日誌的資深前輩，揭露從傳統「警報疲勞與無意義統計」突破至「自研 11 隻 MCP（Model Context Protocol）工具串接 Claude Desktop」，實現 3 分鐘自動化攻擊鏈重組、CVE 關聯分析與 CTI 情資產出之完整架構。

## 🎯 開場引言：主動防禦的誘捕哲學與 T-Pot 平台

**【大會主持人】**：接下來這場議程，是由兩位講者為我們帶來「TIPa 與 AI 驅動的威脅分析實戰」，讓我們以熱烈掌聲歡迎兩位主講人！

**【蔡全宇 (Leo)】**：大家好，今天這四十分鐘，我希望能跟大家分享「從 TIPa 蜜罐誘捕到 CVE 漏洞威脅分析」的主題。

先跟大家自我介紹，我叫蔡全宇。我今年準備升大一，從高中就開始接觸資安領域，去年以 TIPa 蜜罐為主題參加資訊服務應用創新競賽並榮獲獎項，很榮幸今天能有機會向各位先進分享。

首先跟大家介紹：什麼是 TIPa / T-Pot 蜜罐（Honeypot）？大家可以把它想像成大自然中的「捕蠅草」，或者像蜜罐吸引蜜蜂一樣——我們故意在網路上模擬出具有已知漏洞的服務當作誘餌，把駭客當成蜜蜂吸引過來，並完整記錄下他們的入侵路徑與操作行為。

在過去如果我們要架設蜜罐，往往非常繁瑣，需要手動安裝配置許多零散工具。但 T-Pot 這個開源平台把所有東西全部打包整合在一起。我們架設蜜罐主要有四個核心目的：
1. **設置誘餌**：模擬具備真實漏洞的網路服務，引誘攻擊者前來嘗試攻擊；
2. **捕捉手法**：完整觀察攻擊者連線進來後，敲了哪些指令、使用了哪些工具；
3. **分析趨勢**：統計攻擊手法與熱門目標，進一步轉換為高價值的 CTI（Cyber Threat Intelligence）網路威脅情資；
4. **主動防禦**：跳脫被動等待攻擊的防護困局，主動收集第一手真實威脅數據。

蜜罐在技術上主要分為兩大類：
- **低互動蜜罐（Low-interaction Honeypot）**：僅模擬服務協議的回應，安全性極高、不會被當作實體跳板，但收集到的深入情資相對有限；
- **高互動蜜罐（High-interaction Honeypot）**：提供真實的作業系統與應用服務，能捕捉到最深度的攻擊載荷與零日漏洞利用，但維運風險較高，必須嚴格落實網路隔離。

T-Pot 的四大核心優勢包含：
1. **一鍵部署多元蜜罐**：涵蓋 SSH、Web、IoT 物聯網到工控 SCADA 協議；
2. **Docker 容器化架構**：將各個蜜罐獨立隔離在容器內，兼顧彈性與安全性；
3. **內建 ELK Stack 數據管線**：整合 Elasticsearch、Logstash 與 Kibana，提供即時動態視覺化 Dashboard；
4. **集中管理與擴充性**：具備自動更新與模組擴充機制，非常適合教學研究與企業實戰。

## 🏛️ T-Pot 五層架構與核心誘捕矩陣

**【蔡全宇 (Leo)】**：當外部駭客打進來到我們在儀表板看到視覺化圖表，底層主要劃分為五個處理層級：
1. **第一層（T-Pot 誘捕層）**：部署於最前端，模擬各種常見服務以接收並回應惡意流量；
2. **第二層（Log 採集層）**：透過 Filebeat 與 Logstash 將各容器產生的日誌統一抽取收集；
3. **第三層（資料處理與正規化層）**：利用 Logstash 進行欄位解析、GeoIP 經緯度映射與格式清洗；
4. **第四層（儲存與檢索層）**：將正規化後的資料存入高效能 Elasticsearch 叢集進行索引；
5. **第五層（視覺化呈現層）**：透過 Kibana 提供直觀的即時攻擊態勢圖與統計報表。

在 T-Pot 內建的二十多種蜜罐中，幾種最經典的誘捕矩陣包括：
- **Cowrie**：專門模擬 SSH 與 Telnet 服務，負責攔截帳號密碼暴力破解（Brute Force），並完整記錄攻擊者登入後的終端 Shell 命令操作；
- **Dionaea（捕蠅草）**：專門誘捕 SMB、HTTP、FTP 等協議，能自動捕獲攻擊者上傳的二進位惡意程式樣本（Malware Payloads）；
- **Conpot**：專門模擬工業控制系統（ICS/SCADA），誘捕針對關鍵基礎設施的探測；
- **Elasticpot**：模擬未授權開放的 Elasticsearch 資料庫，捕捉針對雲端數據庫的注入與勒索攻擊；
- **Honeytrap**：通用型網路服務誘捕器，自動適應未定義端口的未知連線。

在 Kibana 的後台視覺化分析中，我們可以即時看見：
1. **時空地理分佈（GeoIP）**：在地圖上標記攻擊發起國家的經緯度熱區，並觀察不同時間序列的攻擊尖峰；
2. **熱門目標與字典排行**：統計最常被探測的服務端口，以及駭客最常使用的弱密碼字典排行；
3. **攻擊戰術與手法分類**：區分暴力破解、已知 CVE 漏洞利用與未知探測行為。

在部署型態上，可分為實體機（效能最佳、適合企業長期監控）、虛擬機（如 VMware / Proxmox，適合教學實驗與 PoC 驗證）與雲端環境（如 AWS / GCP，容易直接暴露於公網流量，便於快速擴展）。因為日誌量極為龐大，建議儲存空間至少配置 100 GB 以上 SSD。

最後必須強調安全性隔離：蜜罐系統強烈建議透過防火牆建立獨立 DMZ 網段，嚴禁直接連通企業內部核心生產網路，避免蜜罐本身遭到突破而被駭客反向當作橫向移動的內部跳板。

## ⚠️ 實務維運痛點：每日兩億筆日誌的警報疲勞

**【資深法人資安前輩】**：大家好，接下來由我為大家分享實務經驗。我玩蜜罐系統已經很多年了。

過去我們在法人機構時期，曾經跟教育部全國學術網路（TANet）合作借用多個 Class-C 網段，一口氣在全台學術網路架設了高達 **6,000 個 IP** 的蜜罐節點！後來離開法人後，我們也在 GCP 公有雲上部署了 12 個 T-Pot 分散式感測器（Sensors）。當時我們光是單單一天的日誌進量，就高達 **2 億筆（200M logs/day）**！

剛開始架設的前幾天，看到即時地圖上滿滿的攻擊射線從世界各國飛過來，畫面非常震撼、非常漂亮，長官和老闆都看得非常開心，因為資安是傳統上最難具體看見績效的領域。

然而，當儀表板連續看了五分鐘、十天、到了第九十天時——系統依然每天跑出兩億筆日誌，你會突然陷入巨大的迷惘：「我每天統計這些數字，到底能為防禦帶來什麼實質價值？」

過去在法人，我們每個月都在做重複的人工作業：統計這個月總流量多少、打哪一個端口最多、哪一個國家比例最高、裡面有沒有特定境外敵對勢力 IP，然後寫成厚厚一份報告呈報給上級。複製、貼上、拉報表……久而久之產生了嚴重的**警報疲勞（Alert Fatigue）**！每天面對海量掃描雜訊，根本無法從中快速萃取出具有實戰價值的威脅情資。

而且維運成本非常高昂：
- **硬體成本**：12 個雲端節點匯總到主伺服器，記憶體至少要開到 64 GB，儲存要開到 2 TB 以上 SSD，月租費用驚人；
- **當機崩潰**：T-Pot 預設採 All-in-One 容器共享機制，如果沒有在各 Docker 容器設定 strict memory limits，放個兩三天記憶體洩漏就會讓主機死當無法登入。因此我們特別撰寫了自動重排與限制容器記憶體的自動化腳本；
- **查詢瓶頸**：Splunk 企業授權費極為昂貴，而開源 Elasticsearch 的複雜 DSL 查詢語法門檻極高。每次長官要求「查出最近一個月針對特定服務的攻擊趨勢」，資安工程師光是下語法跑關聯分析就要花 30 到 45 分鐘，甚至系統直接卡死。

## 💡 創新突破：自研 11 隻 MCP 工具串接 Claude 打造 AI CTI

**【資深法人資安前輩】**：面對海量日誌分析的瓶頸，我們決定利用生成式 AI 來徹底重構威脅分析流程！

但如果直接把日誌丟給大模型，會立刻面臨三大致命問題：
1. **模型幻覺（Hallucination）**：大語言模型會自己腦補編造不存在的威脅情節與虛假 IP 歸屬；
2. **上下文視窗暴漲**：面對數百萬條日誌，直接塞進 Context Window 成本過高且難以推理；
3. **缺乏外部工具調用能力**：傳統模型無法直接檢索本地 Elasticsearch 數據庫。

為了解決這個難題，我們選擇採用 **Anthropic 推出的 Model Context Protocol（MCP）標準架構**！

我們發現 Elasticsearch 官方先前的 MCP Server 僅支援集群效能與索引健康度監控，根本不支援業務日誌檢索，且該專案已停止開源維護。因此，我們以此為基底，**自研了 11 隻專為蜜罐威脅情資設計的 MCP 工具（Security MCP Tools）**！

這 11 隻 MCP 工具的功能涵蓋：
1. **攻擊工具與手法排名**：依協議與探測特徵統計最熱門的惡意工具；
2. **單一 IP 深度威脅軌跡檢索**：拉取特定 IP 在 Cowrie、Dionaea 上的所有歷史觸發記錄；
3. **時間戳攻擊鏈重組（Attack Chain Timeline）**：依 Timestamp 串聯攻擊者從埠掃描、暴力密碼猜解到上傳 Payload 的完整入侵鏈；
4. **CVE 漏洞標籤自動映射**：比對 Dionaea 攔截的 Payload 特徵，直接標記其對應的 CVE 編號（例如 Log4j、Spring4Shell、Struts2 等）；
5. **IOC 威脅指標提取**：自動抽取可疑 IP、惡意 Hash、惡意網域名稱並轉換為 MISP / OpenCTI 相容格式；
6. **雜訊過濾與降噪**：自動過濾內部監控掃描與 Shodan、Censys 等公網日常掃描器。

我們將這 11 隻工具部署在本地端，並直接串接 **Claude Desktop**！

現在資安分析師只要在 Claude 介面以繁體中文下達自然語言指令：
> *「請分析昨天晚上針對 Cowrie SSH 蜜罐排名前三的高風險攻擊者，重組其攻擊鏈，並產出標準 CTI 威脅報告。」*

Claude Desktop 會自動透過 MCP 協定，精確調用本地工具抓取過濾後的結構化數據，並在短短 **3 到 5 分鐘內**完成過往需要耗費 45 分鐘的人工作業，產出結構完整的專業報告！

## 🛡️ 防禦閉環落地：工程實踐與 Human-in-the-Loop 原則

**【資深法人資安前輩】**：在推動 AI 驅動 CTI 的落地過程中，我們歸納出四項至關重要的工程準則：

1. **嚴格約束 Prompt 邊界，杜絕模型幻覺**：
   - **明確角色（Role）**：定義 AI 為專業 CTI 威脅分析師；
   - **嚴格範圍（Scope）**：限定查詢的時間區間與目標蜜罐，避免拉取過量數據；
   - **禁止外網猜測**：在 System Prompt 嚴格下達指令：「**僅允許使用 MCP 工具回傳之真實數據進行推理與總結，絕對禁止由外網未驗證資料腦補攻擊者身分或 IP 歸屬**」；
   - **標準化報告格式**：固定輸出包含攻擊摘要、證據清單、MITRE ATT&CK 手法對應與風險評級的制式表格。
2. **高衝擊防禦操作嚴格保留 Human-in-the-Loop（人工介入）**：
   - 很多技術團隊夢想「AI 分析完直接自動聯動防火牆阻斷 IP」。這在實務上**極度危險**！
   - 例如我在公司內網測試蜜罐時，掃描最頻繁的 IP 往往是我自己的開發主機；如果讓 AI 全自動下發阻斷規則，甚至誤判微軟 Office 365 或 Google 的合法流量，公司的核心生產網路會在一分鐘之內全面癱瘓！
   - 因此，威脅分級處理原則為：
     - **高風險頻繁攻擊 + 明確惡意 Payload**：產出封鎖建議清單，經分析師一鍵審核後下發防火牆 / IPTables；
     - **疑似自動化掃描**：放入觀察名單或實施動態速率限制（Rate Limit）；
     - **低頻偶發探測**：僅記錄於 CTI 數據庫；
     - **內部開發與檢測主機**：建立白名單排除機制。
3. **IOC 自動化轉換與跨平台聯防**：
   透過開源專案將 T-Pot 收集到的情報萃取為 IOC，對接 Wazuh、MISP 或 SIEM 平台，實現情資的跨系統共享。
4. **威脅分析生命週期（Intelligence Lifecycle）閉環**：
   從**收集（T-Pot 誘捕）**、**處理（Logstash 降噪）**、**分析（MCP + Claude 智能推論）**、**傳播（標準化 CTI 報告）**到最後的**防禦反饋（防火牆名單更新）**，形成具有實戰韌性的防禦閉環。
