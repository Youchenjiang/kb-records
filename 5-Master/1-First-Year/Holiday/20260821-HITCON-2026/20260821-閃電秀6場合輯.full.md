## ⚡ 閃電秀 1：DEFCON Goon 現場維安工作人員招募（Henry）

**【大會主持人】**：來看看不一樣的日常，掌聲歡迎 Henry！

**【Henry】**：剛發現因為我沒有投影片，所以麥克風要切換一下。OK，好，那在場各位如果認識我的話，我是 Henry。那我是台灣黑客社群成員，同時也是 CSA（雲端安全聯盟）與 The Honeynet Project 的 Member。

認識我應該都知道我這個 Community 在做哪些事情，不認識我的話會後也歡迎聊聊。但今年我有兩個特殊的身份，第一個就是呢，我是今年度在 DEF CON 擔任專門的工作人員（Goon）。OK，那另外的話就是我是 DEF CON AppSec Village（DCA Village）的 Steering Committee Member。那這兩件事情其實在台灣比較少人去，我想先看一下在台灣有去過 DEF CON 的有哪些？各位舉手看一下——前排這邊一定都有。

OK，好。大家去 DEF CON 通常是以 Attendee（會眾）或打 CTF 的身份去。但作為 Goon，有人知道 Goon 是做什麼的嗎？Goon 在美語俚語中是指黑幫打手，在會場顧名思義也就是現場維安的活動工作人員。

如果你們在會場看到我穿紅色衣服、戴著 Goon Badge，代表我正在執勤工作中。OK，那如果我今天不是穿紅色的衣服，戴著 Badge 是以個人身份參加會議。最主要一個不一樣的地方就是會很操！我們有分很多不同的部門，我是在 Goon 裡面大概最操的部分，也是像會場這邊大家在維持秩序的活動人員一樣，我們等於是 DEF CON 的保安人員。

如果大家有去過 DEF CON 的話應該知道，你們就是要「Get in line!」。不論去聽演講也好、要買東西也好、要吃東西也好、要幹嘛都好，會有一群穿紅色衣服的 Goon 在那邊大喊「Get in line!」，叫大家排好隊。OK，那 Goon 是所有 DEF CON Organization 裡頭當中的分支，當然還有很多其他的像是 Speaker 團隊等等，整個 DEF CON Organization 大概有 400 多人，光是 Goon 本身就有 200 多人以上。

OK，那大家可能不知道，身為 Goon 其實完全是一件體力活！我們每天分三班，每班是八到十個小時。我這一班是 First Shift（早班），所以從早上 5 點半開始到下午 3 點半我都在會場。所以在各位進場之前，其實我們就已經在會場做準備，準備會場所有這些不同的佈置、拉線，或者處理大家進場的動線問題。

所以呢，我為什麼今天會在這邊講這些事情？其實我是來做招募（Recruitment）的！OK，那也因為我們現在在 DEF CON Organization 看到亞洲區來的會眾其實越來越多。我們今年算了一下，韓國、日本、台灣跟其他亞洲區算起來所匯聚的人數，大概有將近 600 到 700 人左右。

OK，雖然今年度整個大會 Total 大概有 35,000 人，可是光是亞洲區就我所知道的大概就有六、七百人。這六、七百人要由 200 多位外籍 Goon 去協助其實有點困難。像我今年在當 Goon 的時候其實就被拉來扯去，因為我是裡頭唯一會講中文的！OK，那現場要維持秩序、外籍保安不知道該怎麼應對時，我就必須過去用中文溝通處理。

所以我今天就是來招募：如果你們對自己有信心，每天可以走 3 萬步不休息、可以連續工作 10 個小時不坐下來、願意早上 5 點鐘起床工作到下午 3 點半再回去睡覺的話，OK，我們非常歡迎你加入行列！那有什麼好處呢？好處多多：第一、免飯店住宿費；第二、免伙食吃飯錢；第三、全場任何排隊都可以直接插隊！買周邊、吃飯、聽熱門演講都可以插隊，擁有全場最高 VIP 特權！

OK，那結論如果你們想加入的話可以來找我，我們今年已經在 DEF CON 成立一個新的亞洲組織叫做 **A49**。OK，所以希望有機會邀請大家！謝謝大家！

## ⚡ 閃電秀 2：讓 HITCON 成為你的知識庫——HITCON KB 2.0 (HITCON Wiki)（克雷）

**【大會主持人】**：下一位講者是克雷，帶來的主題是：讓 HITCON 成為你的知識庫——HITCON KB 2.0 (HITCON Wiki)！這是一個以正體中文資安內容為主的知識平台，掌聲歡迎克雷！時間倒數計時開始！

**【克雷】**：好，大家好，我是克雷。這次主要是因為專案剛推出，所以我被推上來講 HITCON KB 2.0。我們的主題是希望「讓 HITCON 成為你的知識庫」。

因為我剛才知道時間一到訊號會被切斷，所以我決定先講最重要的東西以免被切斷！在講投稿之前，先跟大家介紹一下 HITCON KB 的獎勵辦法：我們目前規劃了優渥稿費、實體與數位獎狀、獎盃與感謝函，還有專屬紀念品包含 HITCON 年會門票！額外獎勵據我所知，優質作者有可能受邀親自上台演講，還有擔任 Keynote Reviewer 等，目前我們也在爭取更多獎勵。所以如果各位有興趣的話，非常歡迎投遞文章給我們 HITCON KB 委員會審核。

最近很熱門的是 LLM Wiki，但很多人弄成 Wiki 後都沒在看。我們這個不一樣：這是正體中文資安文章收集、結構化學習路徑，並有 HITCON KB 審稿委員會把關，同時與 HITCON 年會活動呼應。這樣做的好處是——大家知道不管在 iThome 鐵人賽或網路上學到的資安文章，常常資訊不確定、內容衝突、重複，或者只想學一個 SQL Injection，卻莫名其妙被引導到奇怪的地方，結構上比較混亂，沒有辦法得到完整結構性的教學，這正是我們想解決的痛點。所以我們成立了 HITCON KB 審稿委員會對每篇投稿品質把關。大家在 HITCON 常因為講者太強而聽不懂，未來 HITCON KB 會增加更多前置知識與背景上下文。

好，這個是投稿的方式，投影片左邊是投稿表單，右邊是 HITCON KB (HITCON Wiki) 的連結，歡迎大家掃描。我們之後會在 HITCON KB 2.0 裡面同步放出這些投稿表單。我們非常希望大家不論你是新手、或是剛學完一個主題、或任何想分享的內容都可以在這邊分享，不管是第一次去 DEF CON 的遊記、或是你發現了一個很厲害的漏洞、或是你對某個學習路徑有特別的感想或主題，都可以來這邊投稿試試看。

我們這邊投稿除了審核 Accept 之外，還會請你修正或 Reject，若是需要修正都會具名附上理由說明，告訴你可以如何修正。那我們的評分方式有幾個標準：技術難度其實是權重最小的一個指標，我們最看重的是**系統性、完整性與詳細程度**！即使只是重寫一次 SQL Injection 是什麼，只要條理分明、結構完整，也能拿到很高分，所以大家完全不用擔心門檻。

如果大家對 HITCON Wiki 或是 KB 有任何想法，歡迎直接寄信到 `wiki@hitcon.org` 或者直接瀏覽 `wiki.hitcon.org`。謝謝大家！

## ⚡ 閃電秀 3：極致 Cyberpunk 中二 C2 框架 Mina（Ray）

**【大會主持人】**：《Mina 誕生於神話，凌駕於神話之上》！Minerva 是羅馬神話中的智慧女神，今天談的 Mina 是什麼？掌聲歡迎 Ray 為我們揭曉！

**【Ray】**：我講話速度可能有點快，Sorry。好，今天的 Lightning Talk 時間超短。小時候大家都有當駭客的夢想，例如看電影裡的《匿名者》或玩遊戲《看門狗》（Watch Dogs）。第二個是入侵通訊設備，畫面大概是長這個樣子——那個球跑到對面，然後就突然入侵成功，哇好帥喔！從那之後心裡就立志要成為一個超強的駭客。

好，自我介紹一下，我是 Ray，目前就讀台科大，持有包含 OSCP 和 OSWE 在內的 7 張 OffSec 認證。以前以為當駭客很帥，但實際上成為 Hacker 時工作畫面卻長得很微妙，這波直接被搞破防了！難道真的沒有又帥又好用的工具嗎？有 C2（Command and Control）！我到 C2 Matrix 上面找 Mythic C2，好用是好用，但 UI 看起來真的很普通。既然市場上沒有帥氣的介面，那我直接重寫一個——這就是 **Mina C2**！

大家可以看一下它的介面大概是長這個樣子。它有很多功能，但最重要的是什麼？——先進簡潔的 Cyberpunk UI！不知道大家有沒有玩過《電馭叛客 2077》（Cyberpunk 2077）？我特地下載了《電馭叛客 2077》官方美術設定集好好研讀一遍。朋友說我整個 C2 語法和介面都靠中二病在撐場——被你說對了！

Demo 跑起來大概長這樣，非常有感覺！實際上用起來呢，拿到 Session 後點進多節點頁面，下 Command 後 Output 被漂亮印出來，超帥！看看 2077 裡的駭客怎麼戰鬥：放一些 Quickhack 快速黑入，敵人就倒下了，我們在 2026 年的現實中也能做到！大概就像這個樣子：在靶機 Harvest 到的 Hash 可以直接自動解析發送到 Credentials 模組，自動連接到 SQL 資料庫，功能超方便。

另外，不知道大家在打紅隊時會不會聽音樂？我個人聽音樂時最專注，所以在 Mina C2 中加入了其他 C2 框架都沒有的「音樂播放器功能」，邊打靶邊放歌，超爽！

講了這麼多功能，那聊聊開發過程：我大概是去年 12 月的時候第一次測試 Execute，然後今年 1 月 8 號開始全速開發，1 月 10 號就開始內部封測了——只花兩天就生出來！大家可能會想：怎麼可能在這麼短的時間內生出這麼大的專案？我小時候夢想有一台機器，只要把想法丟進去，它就能把你的想法實現出來。沒錯，我畫風一轉：**整個專案全部都是靠 Prompt Engineering 生成出來的！**（全場笑）

Prompting 是什麼意思？就是下提示詞。老實說，除了修改變數名稱以外，我核心程式碼其實一行都沒寫！實測下來，GPT 是我乾爹，可以完成大部分基礎架構；但後來拿去給 Claude 生成，被我罵爆之後，Claude 居然把我罵的點全部修好、完美寫完了！所以這波必須給 Claude 按個讚！

專案跑起來的感覺就像動漫裡的酷炫畫面。後來發生了一件有趣的事：因為開源版本發布後，有個來自烏克蘭的用戶問我能不能開放測試。我去看了一下他的背景，他是烏克蘭當地的藍隊廠商！更酷的是，我去查了一下當時的俄烏戰爭地圖，哇，他所在的區域當時真的正在遭受轟炸，他居然還在砲火中測試我的 Mina C2！總之，Mina C2 超帥，感謝大家支援，我的短講到這邊，大家可以掃描投影片上的 QR Code 去 GitHub Star 一下，謝謝！

## ⚡ 閃電秀 4：HITCON 2026 活動組幕後除障血淚史（活動組）

**【大會主持人】**：第四位是 HITCON 2026 的活動組！今年我們的各種精彩活動能順利進行，背後是我們一大群工作人員夥伴長時間籌備的成果。今天活動組究竟遇到了哪些離奇鳥事的狀況？讓我們歡迎活動組上台！

**【年會活動組】**：沒想到已經開始倒數了喔！好好好，反正這是去年的簡報投影片，我們隨便改一下就上了。我們本來是「約翰與他的快樂小夥伴」——喔不對，我們最愛的約翰離我們而去了，他去美國執行他的安心生育計畫了，所以現在沒有約翰。結果約翰又不知道從哪裡撿到了好幾個 GPT 的企業帳號，所以我們現在隊名改成「撿到了 AI 與他的快樂小夥伴」！（全場笑）

這個路邊撿來的帳號怎麼用都用不完，我們團隊狂用了一週，額度居然還剩 91%！過去三年簡報我們都信誓旦旦說「我們明年要休息」，結果這樣一講反而造就我們今年辦了更多活動，那我們今年到底有沒有休息到呢？——結果還是完全沒有！

第一個活動是我們的 **Badge Quest（識別證解謎闖關）**：我們把 2024 年庫存的 Badge 拿出來辦解謎活動，表面上說是活動，其實是為了要斂財把庫存賣掉啦（笑）。現場不知道大家有多少人解出來，反正我們最後一關的通關答案叫做「撞爆豬肉」！

另外還有兩題挑戰結果出得超級難，根本沒人解得出來，我們準備了 30 幾個獎品，最後居然只發了 2 個出去！投影片這邊大家自己拍照留存，想知道解法的自己回去研究。

再來是我們今年的重頭戲大活動——**Card Battle（智慧卡卡牌對戰）**！一定有人想問：為什麼今年 iOS App 沒有成功在 App Store 上架？因為年會前一天 iOS App 來不及通過審核，我們緊急申請加急審查，結果 Apple 審核員拿到測試 Token 卻回報說「我不會登入」！

然後現場的製卡印卡機也出事：皮帶斷掉、轉向機構卡死、外蓋打不開！這台是銀行退役的二手舊機台，現場幸好有熱心會眾幫忙拆解修復，但修好後發現缺乏機械潤滑油。這時我們靈機一動，拿了雪玉從美國帶回來的「甜筒口味護唇膏」直接充當齒輪潤滑劑！所以現場大家拿到的卡片，可能都帶有一股甜筒的香甜氣味！

今年 Card Battle 總共有 728 人註冊帳號，624 人成功收集到卡片。

很多人問說 Card Battle 的隱藏成就是什麼？其實是一個叫做「釣魚」的彩蛋。解鎖方式是把特殊卡裡面的網址複製出來，只要點開就會被扣 10 分。結果會眾發現點了會扣分之後，竟然開始寫 Script 瘋狂扣自己的分！今年最後一名刷新紀錄——扣到「負 700 萬分（-7,000,000）」，直接把我們的伺服器資料庫給打掛了！會眾還做了「渣男渣女排行榜」，統計誰掃了別人最多次卻從來不回掃別人。

另外頭貼部分，大家發現可以用高畫質頭貼，上傳任何 PNG 圖片印卡機都會接受並印出來。

**【活動組 出題關主】**：大家好，我是負責設計 Red Tape 挑戰的人。Red Tape 是靶機平台上有 5 個漏洞，利用漏洞寫入 Flag 佔領靶機。我們寫好前端畫面後現場出現 Bug：預期 Output 顯示正常，但底下 Capture Log 越來越長，把版面整個擠爛，導致旁邊的 Sidebar 完全被遮住看不到了！因為現場不敢亂動 Production 程式碼，我們直接打開瀏覽器 F12 開發者工具，用 Selector 找到那行有問題的 CSS 直接刪除，畫面就瞬間修好了！（全場大笑）

**【年會活動組】**：還有現場的 PCB 焊接體驗，提醒大家焊完記得要洗手，今年全場達成「零受傷」紀錄！最後，原本預計要推出的自動烤棉花糖機因為難產，最後只剩下飲料機。活動組下台一鞠躬，謝謝大家！

**【大會主持人】**：好，非常感謝活動組！大家請把熱烈掌聲送給背後辛苦的活動組工作人員！

**【阿斯卡】**：大家好，我相信用過 PowerShell 的人都覺得這是個很怪的東西。雖然現在跨平台都可以跑 PowerShell，但我相信大家在 Linux 或 macOS 上絕對不會想用 PowerShell。快速講一下 PowerShell 到底有哪些怪東西：首先它支援 Tab 補全、不分大小寫；支援直接載入 C# 程式碼調用 Windows API；還有很奇怪的內建變數，像是我很喜歡用的 $ExecutionContext，你可以一路往上爬並執行各種操作，甚至可以直接在裡面執行 Inline Assembly！它的跳脫字元不是常見的反斜線，而是用 Backtick（反引號 `）；參數名稱只要打前幾個字母就可以自動辨識縮短。

但這些都不夠怪，前幾個月我發現了一個更冷門、更隱蔽的機制——**PowerShell TypeData 屬性覆寫（Override）**！

PowerShell 允許透過 TypeData 自訂或覆寫 .NET 物件的屬性與成員 Getter。我們要怎麼 Forge（偽造）東西呢？例如：我們可以直接覆寫 System.IO.FileInfo 的屬性 Getter，將惡意 Payload 注入其中。當管理員在終端機鍵入常規的 `ls`（Get-ChildItem）列出目錄檔案時，背景便會自動觸發 Getter 內注入的程式碼！

另一招是利用 `System.Management.Automation.PSVariable` 偽造變數屬性，讓 `Get-Variable` 只顯示看似正常的數值以規避安全檢測。更絕的是在 `CodeProperty` 塞入成員，每次目錄進行 Enumerate 列舉時都會自動執行注入的程式碼。最關鍵的是——**這種手法完全不留下任何 PowerShell ScriptBlock 日誌**！因此 EDR 與 SIEM 監控根本抓不到！

你可能會想說為什麼要這樣做？因為在物件屬性裡塞一行執行代碼，日常維運根本不會有人察覺。公開的 PowerShell 資安研究中我也幾乎沒看過有人這樣用過。如果有人想用 `Get-Member` 去排查，但別忘了 `Get-Member` 本身的輸出也是可以被 Override 掉的！我的分享就到這邊，謝謝大家。
