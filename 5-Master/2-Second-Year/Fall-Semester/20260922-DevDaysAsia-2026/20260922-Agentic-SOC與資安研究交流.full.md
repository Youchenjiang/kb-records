## 🎙️ 第一部分：Agentic SOC 演講——Security Copilot 與威脅狩獵 Agent

複核的時候還是可以去把它複核認為說它不是有問題，也許是一個 Pentesting 是一個正常的白名單之類的東西。好，那這個就是因為有一些 Agent，但其實現在的 Agent 在我們的 Agent Marketplace 上有蠻多種的，有一些是我們微軟自己提出來的，那有一些是第三方廠商推出的 Agent，你可以在上面直接使用。

那這個也是微軟自己的，就是 Security Analyst Agent，它基本上就是負責分析，去深入分析 Defender 或者是 Microsoft Sentinel 的原生告警。原生產品的告警資訊有限，你希望它幫你分析得更詳細一點，你就可以去跟它互動。

那當然還有一些對話功能，比如說威脅狩獵（Threat Hunting），這個功能算是我自己認為在 Security Copilot 裡面非常好用的其中一個功能。大家可以看到這邊是我自己用中文去跟 Copilot 確認事情：首先在 Defender 頁面點選三個小點，這邊有個叫做『威脅搜尋（Threat Hunting Agent）』，把它點開來。點開來以後，你就可以問它問題。例如我們今天在調查事件，認為最近駭客蠻多使用 PowerShell 來進行攻擊的，我就請它幫我列出相關威脅。

在以往進階搜捕（Advanced Hunting）原本是需要工程師手寫 KQL（Kusto Query Language）的，現在它查完以後會自動幫你寫好 KQL 語法，並且自動把圖表跟可以下載的報表清單列出來！除了跟你對話以外，圖表與表格全部產出，告訴你這 30 天內有哪一些事件跟 PowerShell 攻擊有關，並把相對應的 Device 設備與關聯識別碼完整列出。

再來關於 Sentinel MCP Server，如果大家希望能自主掌控權限，它可以讀取你的 Log 與資產資料，而且基本上是整合原生服務。如果大家有興趣的話，我們有非常多的官方資源可以參考。另外 MCP 的部分除了內建的三個官方工具外，也支援自定義 API，讓 Security Copilot 透過 MCP 拉取企業內部的特定數據。

## 🔬 Project Perception：前瞻紅藍綠自主對抗與多 Agent 驗證

最後來講一下微軟前瞻的一些前沿研究。如果早上有聽 Evaluation 的話，其實我們有提到一個叫做『Project Perception』。

Project Perception 認為：我們的 SOC 不應該只是停留在被動防守。因為 AI 與 Agent 進步得太快了，如果有個新的漏洞出來，企業如果要等一年一度的外部紅隊演練，那間隔太久了，而且紅隊演練成本極高！

所以我們如果內部有一個紅隊 Agent（Red Team Agent）、一個藍隊 Agent（Blue Team Agent）、一個綠隊 Agent（Green Team Agent，負責修復與驗證），平常一有任何新情資或新漏洞被揭露，或者有新的 Log 被追查出來，這時候你直接把這些資料餵給你的紅隊 Agent，叫它立刻對你的環境發起自主測試，而不是被動等待一年一度的演習！

我們認為用這個方式去驗證企業自己的 SOC 基本架構是更為敏捷且有效的。雖然這屬於更前瞻的 Agent 研究，很多功能目前處於 Private Preview 階段，但它能直接整合在 Defender 與 Sentinel 的介面中。最有趣的是，Project Perception 會把滲透測試（Pentesting）Agent 直接做進去，未來甚至能把上一場所講的 MAGENTA 多模型弱點掃描器搭配滲透測試紅隊 Agent，在企業內部對 Web 應用程式與雲端架構進行持續性的實戰驗證！

## 🤝 第二部分：會後現場深入交流——資安三年研究計畫（紅藍綠架構）與閉環治理對談

（以下為會後現場，用戶 Youchen 與現場資安架構前輩針對『三年資安研究計畫』展開的深度實戰交流對話全紀錄）

**資安前輩**：你現在是在做一套整體的治理環境嗎？

**Youchen**：沒有，我們目前是在執行一個研究計畫，計畫分成了三個部分，就剛好跟台上講的很像，是『紅、藍、綠』三隊架構：一個同學負責修復的研究（綠隊），一個同學負責重建攻擊流程與 PoC（紅隊），還有一個同學負責找出弱點（藍隊）。

**資安前輩**：那你們這部分是只針對 Agent 做，還是針對 AI 生成的程式碼？

**Youchen**：針對程式碼，主要是 AI 生成的程式碼相關的安全弱點。

**資安前輩**：原來如此！現在業界最大的漏洞來源之一確實就是 AI 自動生成的程式碼。台上剛才他們更進一步是在分析 Agent 本身的安全問題，而你們是分析 AI 生成出來的 Code。不過不管是哪一種，走進企業級都脫離不了治理。那你覺得這可以跟你們的研究計畫對齊嗎？

**Youchen**：對啊，我覺得今天聽下來，至少可以跟我們的研究計畫對齊，不會覺得跟業界脫節。

**資安前輩**：那你覺得最重要的是哪一部分？剛才台上講的開發與維護，像除錯、分析與偵測，但最核心的其實是『閉環（Closed Loop）』！你們剛才講的紅藍綠，有把閉環接上去嗎？

**Youchen**：我們目前好像只做到發現與修復，閉環那一段好像還沒真正接上來。

**資安前輩**：這就是最可惜的地方！你們那個閉環沒有接上來。你想想看，紅藍綠三隊合作是為了解決未來的預防性問題。修復只是事情發生之後的補救，就像以前發生重大刑案大家才裝監視器、發生 911 事件後機場才全面升級安檢。可是安檢規則不是由現場的安檢人員或防恐部隊去改寫的，而是由管理整個機場架構的頂層單位去改寫規則！

你們現在紅藍綠三組做完之後，產出的報告交給誰？如果只留在你們自己小組內部，沒有往上回報給『架構者（Architect）』或『規則設計師（Policy Designer）』，那架構者就永遠不會因為你們的發現去改寫底層規格！

頂層架構者改寫了規則之後，開發者根據新規則開發，新規則再交給你們去驗證有沒有漏洞，這才叫閉環！

就像以前台灣各家醫院的健保系統沒有連線時，你看病要自己帶病歷轉診；現在健保署建立了一套中央雲端系統，你在 A 醫院看診，B 醫院就能共享所有就醫紀錄與藥歷。你們現在的研究如果只是各做各的，沒有統一的標竿平台與頂層規格，最後就會變成『三個獨立的屁』，彼此接不起來！

藍隊要做的不只是在自己的小池塘裡摸索，而是要讓河流匯入大海。你們要觀察的不只是 A 到 A 之間的問題，更要觀察中間那條路徑。一定要把研究成果往上收斂成生態系共用的架構規則！

**Youchen**：非常謝謝您的意見與分享！您點出的這個閉環與頂層架構問題非常關鍵，確實讓我們意識到目前研究架構中缺少的一環。

**資安前輩**：不客氣！大家一起交流，方便加個聯絡方式嗎？

**Youchen**：當然可以，非常感謝您！
