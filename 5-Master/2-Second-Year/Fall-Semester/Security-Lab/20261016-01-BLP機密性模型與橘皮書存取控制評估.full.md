## 課堂背景與技術範疇

本堂課為 10/16 資訊安全實務課程的第一節課。授課教師承接上週針對資訊安全多維度防禦之綜述，進一步深入探討電腦作業系統核心之強制存取控制（Mandatory Access Control, MAC）經典理論——**Bell-LaPadula (BLP) 機密性模型**。

課堂開場，教師透過隨堂抽問「No Read Up」與「No Write Down」之核心內涵，糾正學生將 No Write Down 誤解為「不留證據」之常見迷思，並深入淺出地透過古代官階服色、現代軍事機密攜帶（捷運公事包）、公文廢棄處理（清潔工與垃圾桶 vs. 碎紙機）等生活比喻，透徹解析 BLP 的 Simple Security Property（No Read Up）與 \*-Property（No Write Down）。

隨後，教師藉由架構示意圖，詳解特權使用者若不慎執行偽裝為遊戲之木馬程式（Trojan Horse），作業系統若缺乏強制存取控制，木馬將繼承管理者權限私自調取機密並外洩至公共區域；而在 BLP 模型搭配參照監視器（Reference Monitor）的嚴密仲裁下，即使木馬成功執行並獲取機密，最終將機密下寫（Write Down）至低機密等級儲存區的行為將被監視器即時攔截，從而在最後防線阻斷洩密。

最後，教師梳理了美國國防部（DoD）五十年來發展之可信電腦系統評估準則——**TCSEC（Orange Book，橘皮書）** 的七大分級體系（D、C1、C2、B1、B2、B3、A1），闡明各階層在密碼登入、管理介面隔離、安全標籤（Labels）與參照監視器之實務技術演進，並點出防毒軟體與基本密碼門禁在面對人為誤刪或弱密碼攻擊時之防護極限。

**【授課教師】**：修改檔案，不能修改檔案，什麼叫做不能修改檔案呢？我們上週講的是什麼？它有兩個原則嘛，剛剛才說過的，對不對？一個是 Read，一個是 Write，也就是 No Read Up、No Write Down。所以首先，大家一定要瞭解這個 Up 跟 Down 到底是指什麼？對不對？如果我們連這個 Up 跟 Down 指的是什麼都不知道的話，我們在後面討論存取控制就完全沒有基礎了。好，那然後接下來就要看，比如說，我們知道了 Up 跟 Down 是什麼，當然就知道 Read 是什麼意思，讀嘛，對不對？我們讀取資料；Write 是什麼意思？寫入嘛，對不對？

**【授課教師】**：好，再問一個就好，各位同學好。我們柏林呢？你說說看啊。那邊那位同學，你剛剛說什麼？不要留下證據啊？不要留下證據，你覺得 No Write Down 是不要留下證據嗎？嗯，好，為什麼？為什麼會回答不要留下證據這幾個字？嗯，你再想想看怎麼回答啊？不知道啊？好，那老師很快地再說明一次。這表示大家可能有點忘記了。

**【授課教師】**：所以各位啊，你們要找到上這門課的一個節奏。一方面待會兒你們要動手操作，這個是固定的安排；另一方面呢，你們還是要記住老師講的一些重點，這些核心重點能夠幫助你們真正理解網路安全與系統安全的底層概念，這將來在你們某些考試、某些資安專業工作上，都是一定會用到的，好不好？

**【授課教師】**：像這一章所講的，什麼叫做資訊安全？剛才講過這個概念，老師告訴各位，資訊安全其實具有多個面向。我們過去所學的，也許是過去聽人家講過，或者在某些企業教育訓練裡面看到的，那都只是一部分而已。但這門課要告訴大家，它其實涵蓋了多個面向，這也是為什麼這是一門完整的學期課程。

**【授課教師】**：這是我們上次講到的幾個防護面向，資訊安全有這麼多種範疇：實體安全（Physical Security），然後通訊安全（Communication Security）也就是密碼學，透過加密方式保護傳輸；還有電磁波洩漏防護，也就是電磁安全（Emission Security / TEMPEST），對不對？對，還有電腦本體上面的安全，我們剛剛提的就是屬於電腦系統層面的安全。等一下我們會深入講為什麼電腦安全這麼重要，這些綜合起來，才構成了完整的資訊安全體系。

**【授課教師】**：上次已經跟各位說過實體安全與電磁波安全的概念。只要你的設備不發出任何可被截獲的電磁波，或者是做了嚴格的遮蔽，別人就無法探測。所以為什麼很多軍事電影裡面，軍隊出任務或者是作戰飛機出去，都必須保持無線電靜默（Radio Silence）？就是把無線電關閉，因為一旦發射無線電波，敵方就可以透過偵測電磁波的方式來定位你。好，這部分不是今天的重點，我就不再贅述。

**【授課教師】**：我們剛剛講的這個地方，它為什麼叫做電腦安全？它的歷史背景非常非常深厚。這主要是在過去大型電腦主機（Mainframe）時代，其實跟現在的雲端環境非常相似。各位的電腦裡面可能會同時跑好幾種不同的程式，對不對？有些程式是你自己開發的核心業務，但有些程式是外部引進的，比如說有些人從外部下載了一款遊戲程式或工具軟體。你的系統裡面會充斥著各式各樣不同的程式，這些程式的重要性不一樣，最重要的是它們所代表的機密等級完全不同。

**【授課教師】**：尤其在以前大型主機時代，美國空軍（US Air Force）非常在意這一點。因為那時候大型主機非常昂貴，所以軍方必須把許多不同部門的運算工作合併在同一台主機上執行。但是這些運算工作裡面，有些是極度機密、攸關國家安全的重大任務；有些則只是一般部隊或小單位的行政系統，比如說每天上班的打卡差勤系統，通通都在同一個大型主機環境裡運行。

**【授課教師】**：那麼在這種共用主機的環境下運作，國家安全單位最擔心的就是機密外洩。我們說過嘛，如果大家都在同一個環境裡面進進出出，就好像大家一起搭公車或搭捷運一樣。如果你今天是一個身懷國家最高機密的官員，你搭捷運也提著公事包，你想想看，萬一不小心把公事包忘在捷運車廂上怎麼辦？有可能發生對不對？因為公共場所任何人都可以進出，這就非常危險。

**【授課教師】**：所以為什麼當年在國防部的高官、將軍級長官，上下班都必須有專車專人接送，政府重要首長出行都是黑頭黑車？因為他的身分太重要了，不僅是他的人身安全重要，更是因為他隨身攜帶的文件公事包絕對不能跟一般大眾混雜在一起，必須嚴格隔離，對不對？基本概念就是這樣。

**【授課教師】**：問題是，在電腦主機的世界裡，在那個早期大型主機時代，資源非常有限，根本沒辦法做到這麼奢侈的隔離，不可能為每個程式配備專屬主機，大家只能「搭同一班公車」，高官與小兵的程式都在同一台主機裡面跑。在這種情況下，系統該怎麼確保你是 VIP、怎麼確保你的公事包絕對不會被旁邊不同階級的人打開？所以這個難題就丟給了兩位學者去研究解決，也就是 David Bell 與 Leonard LaPadula，這就成為他們經典研究的核心問題。

**【授課教師】**：那他們怎麼設計這個規則呢？很簡單，各位看現在大家穿著不同顏色的衣服，對不對？假設我們規定：穿黃色衣服的人代表 VIP、代表將軍；穿黑色衣服的人代表保鏢或小兵。穿黃色的人，你所有的隨身物件通通貼上黃色標籤；穿黑衣服的人，你的物件都是黑色的。就像古代社會階級一樣，你是什麼官位等級，就只能穿什麼顏色的官服，絕對不能穿錯。你明明是小兵，絕不能穿軍官的衣服；以前在古代穿錯官服是要殺頭的，對不對？

**【授課教師】**：在這麼嚴格的規定下，系統還嚴格限制：你穿什麼等級的衣服，就只能接觸對應等級的東西。所以今天即便大家同坐一班車，你的黃色公事包不小心掉在車廂地上，旁邊穿黑衣服的小兵敢不敢去撿起來打開看？因為法令嚴格規定，只要窺探高於你授權等級的機密就是判死刑，那他敢不敢看？不敢看！這就是所謂的 **No Read Up（不上讀）** 原則！

**【授課教師】**：No Read Up，意思就是你絕對不能往上偷看機密等級比你高的資料。你的安全階級不夠高，就絕對不能去讀取它。在存取控制裡面，每個主體都有一個授權憑證或安全許可等級（Security Clearance），對應到客體檔案也有其機密等級（Classification Label）。如果你的授權等級不夠，就絕對不能讀取高於你等級的物件，這就是保障機密性的核心規則。

**【授課教師】**：好，那什麼叫做 **No Write Down（不下寫）** 呢？上次老師做過一個比喻。我們最怕的是什麼情況？假設你是一位擁有最高機密權限的將軍（VIP），但你想把你所知道的重大軍事機密偷偷夾帶出管制區，或者你被收買了想要洩密，你該怎麼做？如果單位門禁非常嚴格，每個人下班都要搜身、全身搜空，像南非挖鑽石或挖金礦的工人一樣，連口袋都要翻開徹底檢查，那你自產的情報要怎麼送出去？

**【授課教師】**：各位想想看，一般辦公室裡面總會有垃圾桶嘛，對不對？假定單位允許每個人都可以把桌上的廢棄文件隨意丟進公共垃圾桶，而外面的清潔工人每天定時來把垃圾桶收走倒掉。那這個時候，你是不是只要把機密公文揉一揉丟進垃圾桶，自己兩手空空走出大門，清潔工隨後就把垃圾帶出去了，機密是不是就被偷渡出去了？

**【授課教師】**：各位看，清潔工人的授權等級有沒有達到將軍或軍官的層級？根本沒有嘛，他只是一個基層的外包清潔人員。但因為你缺乏規範，機密就被降級夾帶出去了。所以什麼叫做 No Write Down？No Write Down 不是說不能寫字、不是說不能留下證據，而是系統嚴格規範：高等級的人員與物件，絕對不允許將資訊寫入到低等級的容器裡面！

**【授課教師】**：在剛才的比喻裡，公共垃圾桶是向外開放的，它的安全等級是最低的。因此，所有帶有黃色機密等級的文件，通通不准丟進一般垃圾桶！一般垃圾桶只能丟衛生紙，因為衛生紙是完全沒有機密性的最低等級物件。那高等級的機密文件堆積如山該怎麼銷毀？單位必須配備高等級的「碎紙機」！碎紙機本身具備高授權等級，黃色公文只能送進專屬碎紙機碎成紙屑徹底銷毀，絕對不能流入低等級的垃圾桶。

**【授課教師】**：這就是 **No Write Down** 的精髓！你知道的高等級機密，絕對不能寫入、洩漏或轉移給授權等級低於你的對象或容器。如果你是將軍，你回到家絕對不能把國防部防衛作戰機密告訴只有上校階級的部屬，更不能告訴你太太或朋友，因為他們沒有獲得該等級的授權。電影裡的情報員、特工為什麼生活高度機密？因為他接觸的都是最高機密，在體制上完全受到 No Write Down 的約束，一句話都不能往外講。

**【授課教師】**：所以簡單來說，這裡面有一個非常重要的概念：在一個嚴密的系統中，每個人、每個程式都有其授權等級（Clearance），如同進公司佩戴的識別證，或者軍隊裡軍官與士兵佩戴不同顏色的名牌與帽徽。有了這個等級標籤，系統管理者就能明確規範：上校以下能做什麼、上尉以下能存取什麼。

**【授課教師】**：我們再次總結 Bell-LaPadula 模型的兩大基本特性：第一，**No Read Up**，授權等級低的主體不能讀取機密等級高的檔案（保障機密不被低權限窺探）；第二，**No Write Down**，授權等級高的主體不能將資料寫入機密等級低的檔案或儲存區（防止機密被降級外洩）。這兩點大家務必牢牢記住！

**【授課教師】**：那這在現代電腦系統中有什麼用處呢？老師再講一個非常關鍵的實務範例，這個範例希望大家徹底理解。在現代作業系統中執行程式，程式所擁有的存取權限完全取決於「以誰的身分在執行」。你在 Windows 裡面點開一個命令提示字元（CMD），系統常常會詢問你：是要以「一般使用者」身分執行，還是以「系統管理員（Administrator）」身分執行？

**【授課教師】**：為什麼要區分這個？因為同一個程式，如果你以系統管理員身分執行，它就繼承了 Administrator 的最高特權，可以刪除帳號、修改系統註冊表；但如果以一般權限執行，它能做的事情就受到嚴格限制。

**【授課教師】**：回到我們的架構圖。假設在一個傳統沒有強制存取控制的環境中，有一位系統管理員，他平時可以合法讀取公司最機密的機密資料庫（Confidential Data），同時系統中也有一個所有人都可以自由讀寫的共享資料夾或公共暫存區（相當於公共垃圾桶）。如果這位管理者今天不小心被社交工程攻擊，下載並執行了一款包裝成好玩遊戲的「木馬程式（Trojan Horse）」，會發生什麼事？

**【授課教師】**：當管理者執行了木馬程式，這個木馬程式瞬間就獲得了管理者的最高特權！於是木馬背地裡執行惡意指令，直接潛入機密保險庫將敏感資料抓取出來；接著，因為系統沒有限制寫入規則，木馬直接把抓到的機密資料寫入公共暫存區（垃圾桶）。隨後，外部的攻擊者只需要以一般低權限使用者的身分，到公共暫存區把檔案下載帶走，整間公司的核心機密就這樣無聲無息地洩漏出去了！

**【授課教師】**：這就是在傳統自主存取控制（DAC）環境下，木馬程式輕易達成洩密的典型路徑。那如果引進了 **Bell-LaPadula (BLP)** 模型，系統會如何防禦？

**【授課教師】**：在 BLP 模型下，作業系統內部設置了一個關鍵核心元件——**參照監視器（Reference Monitor）**。參照監視器在系統中就像是公務機關的政風單位、警察內部的督察室，或者是明朝的東廠西廠，負責隨時隨地監控所有主體（Subject）與客體（Object）之間的每一次存取行為。

**【授課教師】**：當木馬程式在管理者帳號下執行，並試圖調取機密資料時，因為管理者本身具有高權限，讀取動作本身符合規則；但是，當木馬程式試圖將這份高等級的機密資料「寫入（Write）」到底層一般使用者可讀取的公共儲存區時，參照監視器立刻介入審查！監視器比對標籤：主體此時處理的是黃色高機密資料，但目標容器卻是黑色低等級區域，這違反了 **No Write Down** 規則！參照監視器立刻強制攔截並阻斷這次寫入操作！

**【授課教師】**：各位看，即使前面管理者犯了錯、誤點了木馬程式，木馬也確實被觸發執行了，但在最後關鍵的那一步，因為作業系統強制執行了 No Write Down，機密資料根本無法被寫入低權限區域，攻擊者的竊密鏈路在最後一刻被徹底切斷！這就是安全理論的威力。當你理解底層模型時，你才知道在整個攻擊鏈的哪一個環節可以做出最致命的防禦與挽救。

**【授課教師】**：BLP 模型雖然是在數十年前提出的，但它的影響力極其深遠。尤其在現代國防與高安全作業系統（例如 SELinux、Trusted Solaris 等）中，底層架構早已全面實作了這套機制。

**【授課教師】**：談到存取控制與安全系統分級，就不能不提到美國國防部在五十多年前制定的經典標準——**TCSEC（Trusted Computer System Evaluation Criteria）**，俗稱 **橘皮書（Orange Book）**。橘皮書的核心精神就是「分級分類」，透過標準化的安全要求，將電腦系統劃分為四大類、七個安全等級：

**【授課教師】**：第一類是 **D 等級（Minimal Protection）**，代表最低限度保護。這就像早期完全沒有帳號密碼保護的電腦或傳統電話線，任何人走過去插上電話線就能竊聽通話，毫無安全機制可言。

**【授課教師】**：第二類是 **C 等級（Discretionary Protection，自主保護）**。到了 C1 等級，系統開始要求具備基本的帳號與密碼鑑別；到了 C2 等級，要求更加嚴格，系統必須提供個別登入識別（Individual Identification）與存取稽核軌跡（Audit Trails），一般使用者登入與管理員登入介面必須嚴格區分。目前市面上絕大多數商業通用作業系統（如早期的 Windows NT），普遍能達到 C2 級別的水準。

**【授課教師】**：第三類是 **B 等級（Mandatory Protection，強制保護）**。到了 B 級，系統就必須全面引進我們剛才講的 Bell-LaPadula 強制存取控制模型！特別是從 B1 級開始，所有系統物件與主體都必須被貼上安全標籤（Labels），資料在建立的當下，承辦人就必須明確標記其機密層級；系統在每一次讀寫時均由參照監視器強制仲裁。B2 與 B3 則進一步要求系統架構具備模組化隱藏與高度結構化抗滲透設計。

**【授課教師】**：最後最高等級是 **A 等級（Verified Protection，驗證保護）**，特別是 A1 級。A1 級要求系統從最初的安全架構規格設計、原始碼實作，一直到編譯產出，必須全程通過嚴格的數學形式化方法（Formal Verification）證明其不存在安全漏洞與隱密通道。這在工程實務上的成本極高，通常僅用於絕密級別的國防軍事核心系統。

**【授課教師】**：所以大家要明白，真正健全的資訊安全體系，是將多個層面緊密結合在一起的：實體環境要靠門禁系統與保全防護，通訊傳輸要靠現代密碼學加密，電磁輻射要靠防遮蔽避免外洩，而作業系統本體則必須仰賴嚴密的強制存取控制模型。

**【授課教師】**：這也就是第一章的核心概念——資安防禦是一場與攻擊者永無止境的對抗。絕對不要妄想買了一兩套防毒軟體或防火牆就能高枕無憂。舉個簡單例子：防毒軟體固然能偵測已知的病毒或惡意程式，但如果是使用者自己下達指令把整個硬碟磁區格式化（Format），或者自行執行了危險操作，防毒軟體根本救不了你！同樣地，帳號密碼門禁雖然能防範外部人員，但如果使用者的密碼隨便設成 123456，攻擊者不費吹灰之力就能猜中；或者未來的章節我們會學到，透過精巧的邏輯漏洞繞過身分驗證，傳統門禁就會完全失效。
