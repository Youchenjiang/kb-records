## 執行摘要 (Executive Summary)

本堂課深入解析作業系統安全與強制存取控制（MAC）的經典理論架構——**Bell-LaPadula (BLP) 機密性模型**，並回溯美國國防部 **TCSEC 橘皮書（Orange Book）** 的分級體系：

1. **BLP 機密性雙核心原則**：
   - **No Read Up (NRU / 簡易安全特性)**：主體僅能讀取同級或低於其安全許可（Clearance）之客體，杜絕低權限窺探高機密。
   - **No Write Down (NWD / \*-特性)**：主體僅能將資料寫入同級或高於其安全許可之客體，嚴禁將高機密資料降級寫入低安全容器（如公共暫存區或垃圾桶），杜絕機密外洩。
2. **木馬程式（Trojan Horse）竊密防禦路徑**：
   - 剖析在自主存取控制（DAC）下，管理者執行木馬導致特權被冒用、資料遭下寫至公開區之漏洞鏈路。
   - 闡述引進 **參照監視器（Reference Monitor）** 仲裁機制後，即使木馬成功讀取機密，亦會在「下寫至低權限區」的最後一步被強制阻斷，確立縱深防禦價值。
3. **TCSEC 橘皮書安全分級演進**：
   - 系統化梳理 D（無保護）、C（C1 帳號密碼 / C2 個別稽核與商業系統常態）、B（B1 標籤與 MAC / B2 結構化 / B3 安全網域）、A（A1 數學形式化驗證）之分級特徵。

## TCSEC 橘皮書安全分級評估體系

| 分級大類 | 評估等級 | 核心技術要求 | 實務對應與系統實例 |
| :---: | :---: | :--- | :--- |
| **D 類** | **D (Minimal)** | 無安全保護，缺乏身分鑑別與存取限制機制。 | 早期無密碼終端、傳統電話直連線路、MS-DOS。 |
| **C 類**<br/>*(自主保護)* | **C1** | 基本自主存取控制（DAC），具備使用者名稱與密碼鑑別。 | 早期 Unix 系統、工作群組網路。 |
| | **C2** | 個別使用者識別、登入權限分級介面、存取審計日誌（Audit Trails）。 | Windows NT/2000/XP、現代多數商業發行版標準組態。 |
| **B 類**<br/>*(強制保護)* | **B1** | 導入強制存取控制（MAC）、資料安全標籤（Labels）、BLP 模型實作。 | SELinux (MLS policy)、Trusted Solaris。 |
| | **B2** | 系統結構化保護、隱密通道分析（Covert Channel Analysis）、抗滲透測試。 | 高安全國防專用多階層伺服器。 |
| | **B3** | 參照監視器完全中介化（Complete Mediation）、抗竄改硬體隔離、安全網域。 | 軍事指揮管制核心、硬體級安全隔離區。 |
| **A 類**<br/>*(驗證保護)* | **A1** | 形式化數學規範（Formal Specification）與原始碼數學驗證證明。 | 極高機密國防核心微核心系統（如 seL4 形式化驗證核心）。 |

## 核心結論與行動要點

1. **落實最小權限與強制控制**：在涉及高敏感機密業務之系統架構中，單純依賴 DAC（如檔案權限 chmod 777/755）無法阻擋木馬提權外洩，必須引進具備標籤機制之 MAC 架構（如 SELinux 或 AppArmor）。
2. **參照監視器三大準則**：任何安全核心之參照監視器實作必須滿足：
   - **完全仲裁（Complete Mediation）**：所有存取操作無一例外必須經過仲裁。
   - **防竄改（Tamper-Proof）**：監視器本身運行於隔離受保護區域。
   - **可驗證性（Verifiable）**：代碼體積必須足夠精簡以利徹底審查驗證。
